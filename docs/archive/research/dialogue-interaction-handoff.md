## 給遊戲／故事進程設計

以下是 Nightfall 候選設計，尚未核定：

1. 尋物成果進入對話：證據有明確來源與內容，可對特定說法使用，避免收完物品後只按繼續。
2. 區分「追問」與「舉證」：追問補充資訊；舉證要求玩家選擇證詞與物品的關係，成功後改變說法或解鎖下一事件。
3. 把準備與態度分開：持有證據決定能談哪些內容，對話意圖決定 NPC 如何回應；不必立即加入隱藏好感數值或 RNG。
4. 失敗給可理解的反駁並可返回檢視線索；不可無提示地消耗戰鬥暮晶，或讓缺少可補取線索的玩家卡死。
5. 分支可合流但保留回應差異。若接戰鬥，沿用現有故事暮晶引擎；不因這份研究改職業、傷害與勝負條件。

後續設計需先查現行進程，說明證據取得、可用條件、錯誤回應、取消／返回、完成提交及存檔相容；不能把歷史角色文件的盤點當目前實作。

## 給 UI 設計

以下是 Nightfall 候選呈現，尚未核定：

1. 角色／場景、當前說話者、文字內容、玩家操作保持清楚層級；延續古金與墨綠，文字不要壓在高細節原畫上。
2. 證詞可前後回看，當前句明確選中；證據抽屜可看物品圖片、來源與短說明。
3. 「查看證據」與「提交舉證」分開。預覽與取消不推進故事；提交前顯示正在反駁哪一句。
4. 使用具體意圖文案，如追問時間、出示貨運單、暫時離開。未滿足條件時顯示原因，不只灰色按鈕。
5. 以表情／姿勢、短停頓與文字變化呈現被追問或改口；音效是輔助，靜音與減少動態仍須看懂結果。
6. 觸控、點選、鍵盤有同等操作；長文可閱讀、焦點可返回，不直接照搬主機按鍵標記或限時選項。

共同優先候選：用一個「取得證據→追問→選證據→反駁→人物改口」小事件驗證操作理解，再決定是否擴大。此例為新提案，非已完成內容。

## 劇情與遊戲樹詳細交接（2026-09-25 補充）

使用者追加要求將對話流程與細節交給劇情及遊戲樹。以下全為 Nightfall 設計候選，非兩款參考遊戲已完整觀察的規格，也不代表正式劇情或程式實作授權。

### 對話流程與返回點

| 階段 | 玩家行為／劇情回應 | 遊戲樹需表達的條件與返回點 |
| --- | --- | --- |
| 進場 | 交代人物目的、衝突、當前問題 | 檢查節點前置；依已知線索選開場，不提前標完成 |
| 調查 | 取得物品、讀來源與可觀察事實 | 區分已看見、已取得、已確認的線索；只設故事真正需要的狀態 |
| 聆聽 | 對方提出數句可回看的說法 | 每句有穩定識別與版本；當前選中句不是任務進度 |
| 追問 | 問時間、地點、人物或動機；補充或修訂說法 | 追問可重看；新資訊只解鎖一次；修訂句仍保留上下文 |
| 選證 | 開啟證據詳情，選擇反駁當前句的物品 | 預覽／取消不提交、不扣資源；返回原句並恢復焦點 |
| 舉證 | 明確提交「哪句說法＋哪項證據」 | 以已取得證據與目前證詞版本判定；不用隨機成功率 |
| 不成立 | NPC 說明證據為何不足／不相關 | 留在交鋒，可追問、換證據或回調查；不暗扣 HP／暮晶、不鎖死主線 |
| 成立 | 指出矛盾，對方改口並提出新資訊 | 記錄已揭露的矛盾，阻止連點重複觸發；再進入追問或決策 |
| 決策 | 選擇保護、揭穿或繼續追查等明確意圖 | 每條邊列前置、立即回應及後續旗標；允許合流但保留有意義的後續回應 |
| 結果 | 取得下一線索、返回探索或進入既有戰鬥 | 逐一指定目標節點與失敗／重試返回點；戰鬥結束不直接等同故事收錄完成 |
| 收錄 | 讀完結果並依正式流程提交 | 沿用現行完成／獎勵唯一提交入口；重看與重試不重複發獎 |

### 劇情人員需要補足的內容

- 每段寫明 NPC 知道什麼、隱瞞什麼、為何隱瞞，以及玩家此刻能知道什麼，避免用未透露的設定當解答。
- 每個矛盾附「原句、證據可見事實、兩者矛盾理由、追問補充、成功改口、常見錯誤反駁」。不要只列正確物品 ID。
- 關鍵資訊可回看；錯誤反駁指出推理缺口，但不直接替玩家選答案。普通閱讀與推理預設不限時。
- 選項文案描述行動意圖，不以含糊短詞導向意外的重大行為。分支需交代立即代價及後續呼應；未知後果可保留懸念，但不能省略角色動機。
- 示範事件的貨運單／守衛只是占位構想，不能直接加入正史。是否套入既有節點、證據與世界觀，須由劇情檢查後另提候選。

### 遊戲樹人員需要核對的細節

- 區分互動暫態（選中句、預覽、焦點）、本次節點進度（追問、揭露）、持久進度（已提交選擇、完成、獎勵）；先核對現行實作，再提出最小差異，不擅加存檔格式。
- 檢查缺少證據是否有可達的補取路徑；必要線索不能因錯選而永久消失。若需中斷後續玩，另列存檔與遷移需求，不假設目前已支援。
- 提交時再驗證節點、證詞版本與持有證據；連點只結算一次；退出後的舊動畫／回呼不得改動新節點。
- 列出重新進場、返回調查、戰鬥失敗／放棄／重試、重看已完成節點的預期狀態。沿用暮晶戰鬥，無對話 RNG、無新資源懲罰。
- 後續實作驗收案例：正確舉證、錯誤舉證、正證據對錯句、線索未取得、追問後句子更新、預覽取消、連點、退出重入、兩分支合流回應、戰鬥返回與獎勵不重複。本輪只交接案例，不執行測試。

### 分工與依賴

劇情先定敘事因果與回應，遊戲樹核對前置／轉移／恢復，UI 再依合法行動與原因呈現。兩領域本次只需確認接收及指出依賴，不需開發或另寫長報告。正式實作需產品另立工單指定節點、檔案唯一寫入者與驗收範圍。
