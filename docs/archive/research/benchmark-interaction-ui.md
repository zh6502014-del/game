## 七個可用洞見

### 1. 拿起一張卡，應保持它的物件身分

**機制依據：** S3 明確把拖出與放入當作可設計節奏的事件。[官方訪談](https://hearthstone.blizzard.com/en-us/news/23964694)

**心理／操作價值（推論）：** 原畫、卡名與框體在拿起時保持一致，可能減少「拿錯卡」與「複本是不是另一種狀態」的再辨識成本。這不等於競品所有幀都保持同一 DOM 或尺寸。

**Nightfall 提案：** 以 DRAG-UI-005 的共用卡面為起點，建立「靜止／檢視／拖曳／合法指向／取消」五狀態對照；卡身保持不透明，僅位置、陰影與目標提示改變。故事角色普攻拖的是角色意圖，技能拖的是常駐技能牌，不能互相換成同一種卡片皮膚。

**代價／不適用：** 全卡面放大可能遮住手指下方目標；不用額外 PNG 做五種狀態，也不靠透出背景假裝輕盈。原畫保留既有 fit／crop。

**可驗收：** 九卡種與外觀的 src、比例、卡名、圖示及框體在拿起前後一致；手機手指覆蓋時仍能辨認目標；取消後回原位，沒有殘留複本或狀態改動。這是既有功能的品質檢查，非從零開發拖曳。

### 2. 閱讀卡牌與提交行動，要有不同的可見意圖

**機制依據：** S4 將長按檢視與拖出施放分開，也提供點選式指定操作。[Wizards 行動介面說明](https://magic.wizards.com/en/news/mtg-arena/mtg-arena-state-game-january-2021-01-21)

**心理／操作價值（推論）：** 使用者可以先理解再決定，觸控也有不依賴滑鼠 hover 的閱讀路徑；操作分離有機會降低把閱讀當成出牌的誤觸。

**Nightfall 提案：** 故事既有長按檢視與點選／鍵盤路徑先保留，調查是否能清楚辨識「查看」及「選定待指定目標」。詳情顯示文字、費用與行動對象；關閉後回到原焦點。自由決鬥延續點牌詳情再選擇出牌，不把兩模式的點擊意義悄悄互換。

**代價／不適用：** 長按過於隱藏，不能成為唯一閱讀途徑。現有 350 ms 是 Nightfall 的既有契約，並非量得的 Arena 時間；是否調整需另做真機觀察。

**可驗收：** 短點、長按、跨閾值拖曳、鍵盤檢視各只走一條路徑；預覽後 release 不提交；卡名／多行說明無裁切；Escape 關閉並恢復焦點。觸控與桌面各保有可發現的閱讀入口。

### 3. 指向回饋應說清楚「誰，用什麼，對誰」

**機制依據：** S1 將目標箭頭用於讓旁觀者理解選擇；S2 的指令包含技能及適當目標。[Blizzard 觀戰說明](https://hearthstone.blizzard.com/en-gb/news/16421344)、[傭兵操作說明](https://hearthstone.blizzard.com/en-us/news/23707670)

**心理／操作價值（推論）：** 來源、動作、接收方形成可追蹤的關係，比單一亮框更能降低多角色戰場中的錯誤歸因。

**Nightfall 提案：** 故事已存在箭頭與「目標」標記；以引擎 `legalActions` 為唯一可提交清單，檢查自身技能只指向本人、對敵技能與普攻只顯示相應對象。箭頭尾端保持來源辨識，端點落在目標外緣；古金描邊＋形狀／短標籤，不只依紅綠顏色。自由決鬥維持既有對戰槽／自身 HUD 目標，不假造角色選敵機制。

**代價／不適用：** 箭頭可能遮住 HP；不能為好看增加實際命中範圍而引發相鄰目標誤選。Hearthstone 精確高亮色、吸附與取消行為尚待影片觀察。

**可驗收：** 一至三名角色、相鄰目標邊界與自身技能逐項比對合法清單；箭頭不穿過重要數值；放到非法區不消費暮晶／卡片。點選與拖曳提交相同 action 資料。

### 4. 取消必須綁定提交邊界，不能承諾不存在的復原

**機制依據：** S2 有鎖定前重選；S5 的撤回受對手是否結束回合限制。[傭兵指令階段](https://hearthstone.blizzard.com/en-us/news/23707670)、[SNAP 2024-03-12 更新](https://marvelsnap.com/patch-notes-mar-12-2024/)

**心理／操作價值（推論）：** 清楚區分「仍在選擇」與「已付出成本」可降低探索操作的壓力，也避免按取消後誤以為能抹除已揭露結果。

**Nightfall 提案：** 自由決鬥只在放手提交前取消；故事在 pending／gesture 階段維持 Escape、取消按鈕、無效放置及失焦清理。正式 `act/endTurn` 後只讀結果與播放狀態；不新增已結算回復。有效目標的確認應輕而明確，不增加每次出招都要多點一次的確認窗。

**代價／不適用：** SNAP 的同時提交等待期、Mercenaries 的整隊排程不能直接搬到 Nightfall 每次 action 即結算的故事系統；自由決鬥也不應新增 Ready／End Turn。MTG 的回應與優先權不屬本輪 UI 改善範圍。

**可驗收：** 取消、主指 pointercancel、失焦或旋轉中斷後，snapshot／費用／行動額度不變。多指遵守最新故事契約：次指忽略，不更換來源、不提前提交；主指正常完成至合法目標仍可提交一次，主指收到 pointercancel 才取消該手勢而不提交。演出期間的多餘輸入不能排成下一個隱藏動作。

### 5. 可操作狀態要解釋限制，而不只是把牌變灰

**機制依據：** S4 的 Foretell 範例讓可用替代模式與不可施放的普通模式分開呈現。[Wizards 模式選擇說明](https://magic.wizards.com/en/news/mtg-arena/mtg-arena-state-game-january-2021-01-21)

**心理／操作價值（推論）：** 玩家需要知道「為何現在不行」以及「怎樣才會可用」，單靠顏色只能提示拒絕，未必能支持下一個決策。

**Nightfall 提案：** 檢查故事既有 `unavailable` 與 `aria-disabled` 文案，讓「暮晶不足」「本回合已施招」「暈眩」「效果已存在」在閱讀時可取得。卡上常駐數值使用徽章；選取時必要才補原因。自由決鬥維持實際封鎖／合法出牌判定，不用故事暮晶文案套過去。

**代價／不適用：** 不在每張小牌塞入全部規則，也不讓 UI 另算一套技能合法性。對未知反擊／隨機結果不得畫成保證傷害預覽；只是顯示已知費用和限制。

**可驗收：** 每種禁止原因有對應文字而非僅灰階；失能牌仍可查看；原因與引擎清單一致，放大文字不擠掉卡名／費用；同一狀態在卡面、詳情與目標提示使用相同 SVG 語意。

### 6. 演出應展開引擎已決定的因果，讓變化有來源

**機制依據：** S3 區分施放與命中節點；S2 明確區分命令輸入與自動演出。[Hearthstone 製作訪談](https://hearthstone.blizzard.com/en-us/news/23964694)、[Mercenaries 戰鬥階段](https://hearthstone.blizzard.com/en-us/news/23707670)

**心理／操作價值（推論）：** 先看出發生的動作，再看到對應對象的變化，可能減少「數字先跳完，角色才動」的理解斷裂。這不是要複製對方時間長度。

**Nightfall 提案：** 故事已有 `frames.before/after/events`，以其為唯一數值來源，檢查選中施放者、作用目標、護盾吸收、HP 變化、倒下的視覺關係；多段事件不能變成同時滿屏浮字。自由決鬥從既有結果事件接同樣語意，不引入故事引擎。音效交 FX agent 對齊實際命中節點。

**代價／不適用：** 不為演出重新結算、消耗 RNG 或套用傭兵速度排序；避免增加無法略過的長等待。減少動態仍要交代來源和結果，靜音仍可讀。

**可驗收：** 一次護盾吸收＋HP 損失、閃避＋反擊、回合開始灼傷及致死案例逐一比對事件；最後 HUD 等於 after；取消播放／離開後沒有舊事件污染新局；減少動態保留必要狀態與結算文字。

### 7. 漏看一拍應能查回來，不必把全部資訊常駐在戰場

**機制依據：** S1 提供歷史與增益查看，S5 加入被破壞／棄置卡的查看入口。[Blizzard 觀戰說明](https://hearthstone.blizzard.com/en-gb/news/16421344)、[SNAP 更新](https://marvelsnap.com/patch-notes-mar-12-2024/)

**心理／操作價值（推論）：** 可查證的結果能支持玩家在注意力移開後重新理解戰局；這可能比再加常駐小標籤更節省視覺負擔。

**Nightfall 提案：** 自由決鬥已有戰況紀錄，故事已有訊息／事件；先檢查最近一次行動能否說出「施放者／技能／接收者／護盾與生命差額」，需要才增加緊湊的最近事件入口，詳細內容留在既有紀錄。持續狀態保留圖示與名稱，日夜由背景暗示，維持使用者取消中央日夜標籤的決定。

**代價／不適用：** 不搬入不屬 Nightfall 的墓地／棄牌區，也不記錄尚未揭露敵方意圖。隱藏資訊不能因除錯歷史洩漏；文字與 SVG 組合需維持安全渲染。

**可驗收：** 玩家只看最近事件也能對上當前 HP／盾差額；完整紀錄及純文字匯出可讀；快速多事件、空紀錄、窄螢幕和特殊字元不破版；未揭露的牌仍是統一卡背。

## 待影片／實機觀察，不作為已證實結論

- 傳統 Hearthstone 在桌面與觸控的拿牌、快速點選、返回手牌、右鍵／Escape 取消邊界；多目標效果是否例外。
- Hearthstone 合法／非法目標的實際輪廓、吸附範圍、手指遮擋處理及手牌展開時機。
- 施放→命中→數值→下一輸入的競品時間軸；本輪沒有逐幀量測，不產生毫秒規格。
- GDC 2015 完整演講與可逐段引用的畫面；摘要入口本身不能證明任何具體物理模型。
