# RESEARCH-008-TREE｜卡牌戰鬥的狀態可讀性與資訊邊界

研究日期：2026-09-24。負責：遊戲樹 agent。狀態：**參考已接收，未實作**。本單只新增此文件；未改規則、AI、RNG、存檔或介面程式，未重新執行遊戲測試。目的是給產品、美術 UI、特效音效與工程師下一張工單的依據，並非新增玩法授權。

## 本專案基礎與研究邊界

已讀 [角色規範](../../agents/GAME-TREE.md)、[故事戰鬥介面工單](../story-battle-ui-001.md)、[暮晶契約](../../story-energy-v1-contract.md)，並唯讀核對 `story-energy-engine.js` 的 `legalActions/act/endTurn`、`story-energy-ui.js` 的 `unavailable/legalTargets/display`，及 `game.js` 的 `canPlay`。

- **自由決鬥**：玩家提交牌後，AI、翻牌與回合結算自動推進；對方牌與未揭曉隨機結果不是預覽資料。不要加入 Magic 的插招、priority 或 stack。
- **暮晶團隊戰**：我方逐角色普攻／技能，結束回合後由引擎完成敵方回合。現有 `legalActions` 決定合法目標；UI 已有能量不足、已行動與狀態原因文字。
- **已存在的呈現能力**：`frames[{kind,side,before,after,events}]` 和呈現副本已建立；演出讀已結算事件，結尾對齊 `after`，並有輸入鎖與取消清理。本研究建議延伸此基礎，不能列成尚未建造的新系統。工單記載的 68 原規則案例、22 frames 案例與 320 種子場次是先前驗收，非本輪重測。
- 本研究沒有直接操作商業遊戲客戶端，也沒有其原始碼。下列「來源事實」限定到官方文件／開發者原始訪談；「推論／候選」是對 Nightfall Duel 的設計建議。

## 八個洞見及可採用方式

下列設計轉譯均為**本專案推論**，不是原作內部實作說明。

| 洞見 | 來源依據 | 自由決鬥的應用 | 暮晶團隊戰的應用／不採用的部分 |
| --- | --- | --- | --- |
| 1. 玩家應立即知道「現在誰能操作」，自動化不應看起來像按鈕失靈。 | S1 | 明列選牌、已提交、揭牌、結算與終局；提交後禁止第二次出牌，保留「正在結算」理由。 | 保留既有 busy 鎖；「我方可行動」與「播放敵方行動」明確分開。敵方演出期間不顯示可出招高亮。不照搬 Full Control 或中途插招。 |
| 2. 成本應在承諾前清楚呈現，並保留玩家的策略決定。 | S2 | 本模式沒有暮晶；顯示一次性護盾額度／封鎖等既定限制即可，不虛構費用。 | 既有費用徽章可補共享暮晶「目前 3 → 施放後 0」選取提示。普攻與技能的每回合額度分別表示；不自動替玩家決定施招順序。 |
| 3. 可預測結果與不確定結果必須分欄，未知不是 0。 | S4 | 只顯示我方牌的已知效果與條件；對方未翻牌、硬幣與機率判定保持未知。不得偷看 AI 已選牌來畫傷害預覽。 | 可先提供成本、目標、必定消耗的狀態；若日後做數值預览，確定、條件式、隨機三種語意明示。例如殘影必閃可確定，近戰反擊只標 50% 條件，不能預抽結果。 |
| 4. 所有重要公開狀態應能掃視比較，不必逐卡打開說明。 | S5 | 把已公開封鎖／夜襲／領域與其對象放回角色旁；未知手牌維持卡背。 | 沿用既有狀態列及普攻／技能額度，優先強化「尚可行動」「已耗用」「受暈眩」的不同形狀。只借資訊層次，不把 Slay the Spire 的敵方下一步承諾移植過來；目前 AI 會依當時戰況選擇，提前預告精確目標會改變資訊規則。 |
| 5. 畫面位置與目標標記應回答「誰對誰做什麼」，不能只用顏色猜。 | S3 | 拖曳保持原卡造型，合法放置區提供輪廓與文字；無效放置回原位，不提交。 | 本人技能標本人、敵方技能標合法敵人；箭頭起點保留施放者。敵我側與職業色是不同概念，特效方向不能由色彩反推。 |
| 6. 操作中的卡牌和閱讀中的卡牌可有不同資訊密度，但身份不能變。 | S3 | 手牌／拖曳／放置使用同一素材與卡框，詳情展示完整文字；放大不是換一張牌。 | 技能牌保留固定所有者、費用、名稱，詳情補目標、持續、已生效／待生效等語意。沿用現有點選／長按檢視，不在拖曳中彈出遮住目標的大段說明。 |
| 7. 效果時間序要可追蹤；畫面播放順序不等於規則 stack。 | S1、S4；專案 frames 契約 | 自由決鬥依既有已結算事件呈現攻擊、反擊、灼傷；不得因動畫先後重新計算。 | 在現有 frames 上清楚呈現「施放 → 吸盾／扣血 → 狀態 → 回合開始持續傷害」的既有因果；若日後提供略過，只略過演出，不新增 endTurn／act。不能照抄 MTG 的後進先出，因本引擎沒有該規則。 |
| 8. 驗收要測玩家理解與操作錯誤，不能只看畫面更華麗或種子勝率。 | S6 | 觀察是否誤把封鎖當作 UI 故障、是否理解翻牌後才有確定結果。 | 觀察是否誤認暮晶每人一池、誤把技能未用當作現在可用。使用獨立測試者與本機紀錄候選，不新增外部分析服務；按經驗程度分組記錄，沒有樣本前不下效益結論。 |

### 「無法行動」提示候選

目前 UI 已存在部分原因，不建議重做一套互相矛盾的判斷。下一張工程工單可評估讓規則原因與 `legalActions` 共用同一檢核來源；在獲授權前，不改引擎 API。

| 原因層級 | 玩家文字候選 | 呈現方式 |
| --- | --- | --- |
| 呈現暫鎖 | 戰鬥演出中 | 全局短提示；不假稱角色已耗用。 |
| 回合／終局 | 目前非我方行動／戰鬥已結束 | 控制區狀態；詳情仍可讀。 |
| 角色狀態 | 已倒下／暈眩，本回合不能行動 | 角色附近的狀態與文字。 |
| 行動額度 | 本回合已普攻／本回合已使用招式 | 分開額度，保留可用的另一種操作。 |
| 費用 | 暮晶不足：目前 2，需要 3 | 同時顯示目前值及所需值，不只整張牌變暗。 |
| 已有增益 | 殘影仍在／人劍合一尚未消耗 | 說明重複施放的限制，避免泛用「待命」。 |
| 目標 | 只能指定本人／請選存活敵人 | 以實際合法清單為準；拖出後退回，不扣費。 |

## 資料契約候選：先隔開四種資料

這是設計草案，並非現在新增的公開介面。實作須另開有允許檔案、基線、工程審查的工單。先沿用既有引擎，不為了預覽在 UI 重寫傷害公式。

```text
權威規則狀態 ── 可見資訊投影 ── 可操作提示／選取預覽
     │                （純讀取，沒有 RNG、沒有 AI 試跑）
     └─ 一次合法提交 ── 已結算 events / frames ── 呈現副本
                                              └─ 對齊 after
```

| 資料 | 所有者與允許讀取 | 禁止用途 |
| --- | --- | --- |
| Authority：現有 S／暮晶 state | 規則引擎負責變更，正式 act／endTurn 才消耗判定 RNG。 | UI 用 DOM、動畫命中位置或音效回呼判傷害。 |
| VisibleState：模式＋觀察者可見快照 | 己方手牌、公開角色／HP／盾／狀態、公開費用與額度。自由決鬥隱去對手手牌身份、牌序與未揭曉選擇。 | 把整個權威狀態傳給預覽後只靠 UI 約定「不要看」。 |
| Availability／Preview：只讀衍生資料 | 可包含 `actorId/action/targetIds/cost/reasonCodes/certainty`。確定部分和條件分支分開；未知欄位省略並附原因。 | 為預覽呼叫 act／endTurn 後還原、試跑 AI、複製 RNG 後偷看下一次結果、猜測未知牌。 |
| ResolvedFrames：既有完整 action／turn-start／turn-end | 每個 frame 是已提交結果；以 before／events／after 播放並核對。可由呈現層附 session／序號防止舊回呼污染，不改 state 規則。 | 把 frames 稱為未來預測、逐動畫片段再執行引擎、取消畫面時回滾已合法提交的戰鬥。 |

可見資料的邊界是產品規則，不是由「AI 能不能推算」決定。暮晶 AI 雖只讀公開狀態，也不能因此宣稱其未來選擇已承諾。已結算卻尚在演出的 frame 則是另一種資料：有確定結果，但 UI 應依序展示並鎖住新輸入，避免先看見終值後又跳回舊值。

最小可行順序：先把成本、合法目標和原因校對清楚；再評估有限的純讀取數值預覽。複雜預覽暫時不支援時，明示「此結果含未揭曉資訊／機率」，保留卡片原始規則描述，不能展示看似精確的假終值。無法從共用權威規則安全衍生時，寧可不做數值預覽。

## 候選驗收矩陣

以下是下一張工單的測試設計，**本輪執行 0 項**。工單開始前應列出具體 case ID、分母與合法／不可達組合；本表的桶不是全狀態覆蓋。

| 桶 | 必要案例 | 必須成立的性質 |
| --- | --- | --- |
| LEGAL | 四職業；普攻／技能；本人／敵人／死亡目標；錯誤回合；額度已用；暈眩；能量 0–3；既有增益 | 高亮、原因文字與正式引擎接受集合一致；無效提交不改 state、energy、events、RNG。 |
| INPUT | 滑鼠／點選／鍵盤／單指；拖回、Escape、pointercancel、多指取消；檢視卡片 | 每個合法承諾最多一次；未提交可取消；長按閱讀不消耗操作。 |
| VISIBILITY | 自由決鬥兩份狀態公開部分相同，但對手手牌／牌序／未揭曉選擇不同 | 所有預覽輸出、DOM 與輔助文字相同；對手隱藏資料不成為差異來源。 |
| PREVIEW-PURE | 預覽 0、1、100 次後提交同一合法動作；包含 10%／50% 隨機分支 | 完整權威狀態、提交結果、RNG 消耗及後續序列一致；不得預抽、試擲或保存猜中的結果。 |
| CERTAINTY | 確定扣費；必閃＋可能反擊；槍客第 4 發；未知對手牌 | 確定／條件／隨機／未知語意正確；若未實作某預覽，明列未支援，不填 0。 |
| ORDER | 盾吸收後扣血、閃躲後反擊、回合開始共振、主角死亡、雙方狀態 | 現有 frame 連續，event 次序不變，最後畫面等於最後 after；勝負顯示不超前相關事件。 |
| PLAYBACK | 正常／減少動態；若未來支援略過則加 skip；退出後新局；旋轉途中 | 保留同一已結算結果及 RNG 次數；清除舊 session 回呼；不因略過／動畫完成而再走回合。退出本身按既有契約處理，不能視為同一場仍在遊玩。 |
| READABILITY | 自由決鬥 1440／900／700／390／320；暮晶四橫向尺寸與直向提示；文字放大、素材失敗 | 名稱、費用、合法目標、目前資源、原因在操作位置可辨；必要文字與 hit area 不受裝飾覆蓋。 |
| COMPREHENSION | 獨立新手／熟手走相同 fixture，口述「誰可行動、付多少、作用誰、何者不確定」 | 分別記正確辨識數、誤放／取消數、詢問原因與閱讀時間；沒有前後可比較資料不宣稱 UX 已提升。 |

原規則不變的驗收應比完整狀態／事件／RNG，不能只比較勝負。呈現驗收則應同時證明「順序看懂」和「取消安全」，不能以事件 JSON 正確代替可見畫面。
