# RESEARCH-008｜《底特律：變人》的對話與進程洞見

研究日：2026-09-24。產品整理，供劇情／遊戲樹／美術 UI／工程師交接。**研究與候選規格，不是新增劇情或變更存檔的實作授權。** 本輪閱讀官方資料與開發者訪談，沒有親自遊玩、錄製逐幀影像或量測原作操作時間。

## 一、選項文字是對玩家的承諾

**推論自 D3／D5**：玩家選擇的是態度與行動意圖；若短標籤和實際台詞差太遠，就難以為結果負責。情緒不必都被轉成一個「好／壞」分數。

**Nightfall 提案 N1**：以 C7 為小型檢驗點，清楚區分「親自短程接應」與「交接應隊、繼續追查」，讓玩家知道兩者都延續尋父主線。這是建議措辭，不是已替換按鈕。設計時逐項附「當下行動／當下回覆／後續可引用記錄」，不能把後者包裝成拋棄受困者，除非正式劇本真的如此。

**代價與驗收**：較長標籤需要兩行且可掃讀；劇情 agent 檢查每一選項與實際第一句台詞是否同意圖，美術檢查 390px／200% 文字。禁止靠縮字或模糊詞掩蓋差別。

## 二、調查應改變你有根據能說的話

**依據 D3；Nightfall 提案 N2**：把「看見線索」和「推論線索」分開。選項若依賴文件或觀察，呈現簡短來源，例如「引用剛才核對的日期」，讓新的發言機會具有因果。資訊不足時可以問問題，但不能讓角色突然知道別條線的秘密。

**本專案接點**：現有 `inspect`／`search`、線索紀錄與 C4–C6 的證據邊界。先建立文稿表：線索 ID、取得節點、誰知道、可信程度、哪句對話可引用；是否新加可選對話，另交產品排工。

**代價與驗收**：不能每看一物就彈提示。選兩個重要接點驗收「未取得／已取得／回看／重入」；不得用前端隱藏的未讀文字洩漏答案。證據可以解鎖追問，不直接等於無罪或身世真相。

## 三、章末流程圖應解釋經歷，而非催促立即重選

**依據 D1／D2／D3；Nightfall 提案 N3**：先提供「我走過的路」與「已知仍有其他可能」；未探索內容只顯示不洩漏情節的占位。把流程圖放在收錄後的可選檢視，保持「下一段」為主要操作，讓想繼續故事的人不被反覆中斷。

**現有基礎**：28 節點章節總覽、已讀回看與 C7 選擇紀錄已存在；不能再把一般線性對話步驟畫成不存在的巨大分支。第一版只畫正式資料中確有的節點／依賴／分支。

**代價與驗收**：分支數或鎖定位置本身也可能是劇透；預設只顯示已遇到的局部分支。首次閱讀、全通、重玩、存檔遷移四種狀態，圖上位置與實際記錄一致；未知角色與結局不出現在 DOM、輔助名稱或預覽文字。是否開放全劇透需獨立明示模式。

## 四、短分支可以匯合，但記憶不能憑空消失

**D7 為結構參考；Nightfall 自訂提案 N4**：用「短行動分支 → 即時回應 → 記錄旗標 → 匯回主線 → 稍後自然回應」控制內容量。這不是宣稱 Detroit 使用相同資料模型，也不是所有對話都要分叉。

**本專案接點**：C7 已保存 `help/direct`，C8 第一段會讀取；優先把這個既有例子整理成可審查的因果表，不新增十倍素材。記錄可包含已發生的行動、角色所知及資料來源；同一地點仍用共用背景／角色層，符合[素材預算](../../art-asset-budget.md)。

**代價與驗收**：太少回應像假選擇，太多全域旗標難以維護。候選驗收以「有沒有承諾後果、何時可見」為分母，不以分支數量論品質；每個正式旗標要有寫入點、讀取點、未設定值與遷移策略，無用途旗標不進存檔。

## 五、失敗延續是敘事設計，不是偷改勝負

**依據 D4；Nightfall 提案 N5**：在未來已授權的非戰鬥調查情境，可以評估資訊不完整、關係代價或繞路等後果，讓不理想結果仍有可讀的後續，而非只彈「再試一次」。失敗也要帶出新資訊或角色反應，不能假裝玩家成功。

**不適用範圍**：現在 A2／S3／E3／C3 的勝負／牽制條件保持；尤其 S3 的存活牽制意義不能因借鏡而改成死亡仍過關。增加替代路線需要劇情、遊戲樹與產品共同定稿，不在本輪研究授權內。

**驗收候選**：每種結果有可進行的下一步，退出／重試／收錄清楚，失敗不重複發獎；角色生死或任務未達成不得被 UI 隱藏。

## 六、回看、重玩與正式保存要能區分

**D2 只支持原作存在重玩入口；以下保存契約是 Nightfall 提案 N6**：維持「已讀回看」只讀；「重玩章節」重新走互動；「收錄」才依正式現行規則保存。若重玩會更換 C7 的路線記錄，收錄區應能看出將記下哪個選擇，而非每句台詞都加確認彈窗。

**現有基礎**：`story-campaign.js` 已把 review 與 commit 分開，STORY-SYNC-004 已測回看不重複互動、存檔拒寫／重試和 C7／C8 記錄一致。這些是保護契約，不是待重建功能。

**驗收候選**：回看不改進度、不再觸發戰鬥／獎勵；保存失敗不顯示已永久記錄；相同收錄重入不重複發章；改選後後續台詞／紀錄使用同一版本。全流程測試要用獨立測試存檔。

## 七、緊張感來自場景壓力，不必讓每段對話倒數

**D5 提供情緒與表演協作依據；Nightfall 自訂提案 N7**：一般閱讀允許玩家按自己的速度；重要抉擇前用角色停頓、背景聲、短反應建立節奏。若日後加入限時抉擇，必須定義逾時的行動意義與無障礙模式；不能把打字慢或閱讀時間當作角色膽怯。

本研究未量測 Detroit 原生每種對話倒數。Quantic Dream 的 Community Play 投票計時不等同所有原生對話介面，故不拿它推導 Nightfall 計時常數。

**驗收候選**：減少動態、靜音或 200% 文字仍能理解當前說話者／可選內容；對話未呈現完不誤提交；不用音效作為唯一提示。新錄音與新立繪不是這項提案的必要前置。

## 八、介面可以回應故事，但只能知道已知的事

**依據 D6；Nightfall 提案 N8**：章節選單或營地可以用既有角色圖與一行近況回顧提醒「上次走到哪裡」，比又加一個進度百分比更有敘事感。回應只取正式保存且已對玩家揭露的狀態。

**代價與驗收**：先做數個人工寫好的狀態句，不加即時生成、日期追蹤服務或新大圖。若未存檔／存檔失敗，回顧不得宣稱已完成；不同人物不能知道自己未參與且未被告知的秘密。這是較後順位的質感提案，不先於操作清楚與可靠保存。
