# UI-CLARITY-009｜故事戰鬥資訊重整方案

2026-09-24。產品與美術／UI 已完成本輪討論。使用者需求是針對提供的截圖討論改善；**本輪交付設計方案與獨立布局示意，尚未修改遊戲介面**。

## 產品判斷

截圖中，角色周圍同時出現身分、兩項額度、三個不同位置的數值徽章、姓名及職業。暮晶、技能牌與普攻又分散到右欄和底部。大量場地留白並未帶來清楚的閱讀順序，反而讓視線要在不同區域來回找資訊。

本輪採納美術／UI 的方向：**上方戰況、中央雙列角色、底部單一操作區**。美術細節建立在一致分組之上；維持古金與墨綠、現有角色原畫及徽章數值，不需新增圖片。

## 五項優先調整

| 調整 | 具體呈現 | 保護的資訊與行為 |
| --- | --- | --- |
| 角色卡有固定資訊座 | 肖像下固定放姓名／職業／身分；生命、護盾、攻擊沿同一基線排列，卡外不再散掛數字 | 三值包含 0 與小數仍完整；不改進度條、不改真實數值 |
| 額度與狀態分開 | 普攻／招式各自表示已用或未用；狀態另行排列且可換行，不覆蓋臉或取代職業 | 未用不等於可施放；可用提示依合法行動，暮晶不足／暈眩等原因仍可查 |
| 底部集中決策 | 團隊暮晶 → 全隊常駐技能 → 所選角色普攻 → 結束回合；移除右側獨立長欄 | 每位角色的技能都保留，普攻仍有按鈕替代拖曳，不自動代選目標 |
| 常駐提示減量 | 普通最新事件放操作區上緣；中央只在指向期間顯示必要來源／目標提示；詳細歷史及固定規則留既有入口 | 目標、回合、階段、敵方資源與關鍵狀態保持可見；重要限制不只靠 hover |
| 裝飾有權重 | 一層桌緣、一套角色框、同款數值徽章；最明顯的光澤留給選取／合法目標及主要操作 | 選取、禁用、已用除顏色外也有文字／形狀；不靠增加背景亮度解決 |

技能費用和我方暮晶應在相近視線範圍內。當目前 1 點、招式需要 2 點時，卡上保留費用與招式名，短原因放在資訊帶或選取提示；不以大橫條遮住插畫，也不把「未用」寫成「可用」。敵方暮晶放敵列標頭，讓資源歸屬清楚。

## 桌面與小螢幕的取捨

- 桌面使用上肖像、下資訊座，兩列角色按內容高度居中；1v1 和 3v3 維持相同閱讀順序及主角中央位置。
- 667×375 等短橫屏改用矮版角色元件：小肖像與識別資訊並排，三值同一底線；不把直式卡和所有文字等比縮小。
- 長姓名、多狀態或 200% 文字時，容許內容增高並採單一垂直捲動；操作可到達，焦點會進入可視區。這會牽涉 `touch-action`、拖曳與捲動的區分，必須列入後續實作驗收。
- 不保證最矮螢幕、3v3、全狀態與 200% 文字全部同屏。數值完整及可操作性優先於固定舞台高度。

美術／UI 的尺寸預算、selector 接點、未採用方案及完整驗收清單見 [專責診斷](UI-CLARITY-009-art-review.md)。其中約 200×100 的短高角色卡仍是待實作檢驗的尺寸，不能視為瀏覽器通過證據。

## 本輪討論與交付證據

1. 產品與美術／UI 分別對照截圖和 `story-energy-ui.js/css`，確認額度壓臉、數值外掛、職業與狀態共用位置、側欄與技能分離、短橫屏小字等原因。
2. 美術／UI 回覆並交付推薦方案；產品補充主指控制、未用／可用、操作替代入口及多人／放大文字限制，已納入文件。
3. 產品製作對話內布局示意，可切換 1v1／3v3 配置，點選角色和技能詳情。示意以「角色原畫區」占位，僅比較資訊位置，並非新卡面或最終美術。
4. 對話示意不接入遊戲、不載入戰鬥引擎、不保存真實進度。其窄寬堆疊僅供在對話中閱讀，不能替代正式遊戲的橫屏／直向提示契約。

專案內本次只新增本文件及專責診斷，並更新工作板本工單；另同步上一工單 RESEARCH-008 已收到的劇情接收回覆。沒有修改執行碼、生成圖片／音效、更新遊戲入口或版本引用。未操作使用者的對局。

## 後續實作邊界

優先把「角色資訊座」與「底部操作區」作為同一批有界介面調整，再驗證視覺層級。另開實作時，先指定 `story-energy-ui.js/css` 唯一寫入者並保存基線；保留引擎、AI、RNG、費用、四戰條件、frames 與存檔。既有選取、拖曳、鍵盤、長按檢視、主指取消／次指忽略、播放鎖及返回故事皆需回歸。

驗收至少涵蓋 1440×900、1280×720、844×390、667×375 與 200% 文字；1v1／1v3／3v1／3v3；所有狀態、長姓名、小數徽章、費用不足、素材失敗及減少動態。角色位置改變後也需核對 FX 來源／目標座標。工程審查和產品畫面驗收通過後，才可標為遊戲改善已完成。

本輪尚未驗證正式遊戲新布局、真機觸控、跨瀏覽器、放大文字或玩家理解率；不把設計討論或示意檢查當成遊戲回歸通過。


## 對話示意檢查

已用獨立 Chrome 頁面檢查 1024／736／320px 視窗，各含 1v1／3v3，共六組；實際嵌入寬度為 992／704／288px，無水平溢出或頁面 JS 錯誤。三種寬度均驗證選取角色更新普攻標籤、開啟技能詳情及關閉。另人工查看桌面單人／多人截圖，確認主角居中、三徽章同基線、技能順序與角色一致。

第一次連續調整同一預覽容器寬度時，曾讀到上一個寬度，另一輪詳情點擊亦受重排干擾而失敗；改為每種寬度獨立頁面，先驗證實際嵌入寬度後再操作，最終上述六組通過。這是示意測試程序補正，沒有藉此改正式遊戲或放寬溢出條件。

以上只證明布局示意的有限互動與寬度檢查，未測正式遊戲的 667×375 矮版、200% 文字或任何戰鬥流程。示意使用文字占位，原畫裁切與遊戲 FX 落點必須留待實作驗收。
