2026-09-25。劇情 agent 與遊戲設計 agent 的討論稿；**本次只寫文件，未實作、未新增素材或正史**。已讀 `AGENTS.md`、劇情角色契約與目前 `story-campaign-data.js`，以實際 step ID 核對相關行動。012 正修改尋物／拼圖 runtime，本文件不改其檔案。

## 推薦先做 T1 的紙面撤離規劃

首個候選是 **`T1-step-03`，既有 `evac`「整理已勘查的撤離簡圖，確認備用高地通道」**。這裡本來就是規劃停頓，格蘭有渡垣已勘查的資料，也已存在街口、通道、高地與接應處的概念。將拼回圖塊改成在固定宮格簡圖上連出已知備用路線，比在緊急救援中突然解迷宮更符合行為。

若後續核准實作，應替換／調整這個既有互動，不在原拼圖後再加第二題。完成只是「核對了路線」，接著仍由 `T1-step-04` 暮鐘提早響起、`T1-step-05` 隊員喊原集合點失效，再於 `T1-step-06` 引導居民轉向高地。不要在規劃時洩露後兩步的警報或結果。

| B1-step-02 檢測路況、step-06 護磷改道 | 不優先 | 先驗證儀器才能避開當下擾動，磷也不知道另一條路必然安全。不能把她的能力改成全圖安全路徑提示。 |

| E3-step-03／05／07 組裝、破鎖、追兵戰；C3-step-04 撤離戰 | 不替代／不疊加 | 已有完整因果與操作：組裝蓄能／破鎖／戰鬥，或壓制後門追兵。連通不能繞過任何正式戰鬥條件。 |
| C7-step-07 路線抉擇 | 保留原抉擇 | `help/direct` 是共同決定接應或追查，兩線都繼續尋父。不能把最短路徑自動當成道德正確答案或改寫保存值。 |
| C8-step-02 觀測區資料拼圖 | **不當移動路線** | 這是比對舊資料，尚未抵達觀測區；連通不能暗示實際走過，更不能還原刪除紀錄。 |
| C9-step-01 查備用藏身處 | 後順位 | 分別依筆記、路況、朋友記號與伏擊檢查建立判斷。可日後研究「逐項查核」，不先給一條會自動找到父親的全知路線；現有尋物／接線先保留。 |

S1、S2、E1、P1、P2、B2、C2、C4～C6 的主要行為是交談、核對證據與情緒轉折；即使旁白包含地名或角色移動，也沒有必要都加入宮格。

## T1 試點的可交付語義

| 項目 | 候選定義與依據 |
| --- | --- |
| 操作者 | 格蘭，依渡垣已勘查的簡圖核對；不是控制夜域或重新排列街道。 |
| 起點 | **街口**。沿用既有 `evac-0`，不稱「原集合處」，以免和後文失效的原集合點混淆。 |
| 必經點 | **已勘查通道**。沿用 `evac-1`；任務是核對隊員已勘查、經此通道的備用路線，而不是自由尋找最短路。 |
| 目的地 | **高地接應處**。合併既有「高地／接應處」的地圖語義，表示備用接應方向，不新增中途接應站。 |
| 宮格含義 | 固定位置的簡圖索引；連線是筆跡／核對軌跡。格數不是公尺、分鐘或角色生命成本，不能搬動或旋轉街道來造路。 |
| 阻礙與未知 | 只表現資料裡未連通／未核對的部分。禁止顯示未來夜域、倒數、預知倒塌或敵人移動路徑。 |
| 完成前一句 | 「沿簡圖上的路段，從街口經過已勘查的通道，接上高地的備用接應處。」 |
| 完成後一句 | 「從街口經過勘查通道，已接上高地的備用接應位置；格蘭記住了這條路。」 |
| 未經必經點卻到終點 | 「已連到接應處，但還沒核對指定通道。沿途找出隊員勘查過的通道，再確認路線。」 |
| 斷線／錯接 | 「這兩段還沒有接上，從最後確認的位置繼續核對。」不暗示已有人受傷。 |
| 下一步 | 仍按原順序顯示暮鐘提早、原集合點失效、居民轉向高地；不是按連線長短計算能救幾人。 |

完成回饋是呈現候選，不表示程式已整合。「已勘查」也不等於保證安全；夜域變動後仍需依現場情況行動。簡圖若允許到終點卻不經通道的連法，必須在開始前說明指定通道要求，不以隱藏規則判錯；其他可連格也不能被默認為已確認安全的捷徑。

## 與遊戲設計 agent 的討論結果

共同同意先做 T1-step-03，等待 012 凍結後另派實作單；不碰 T2/T3 的緊急救援，不以迷宮替代戰鬥。遊戲設計提出固定 5×5 作最小候選，屬介面／難度設計，並非已存在的正史街道尺寸。

劇情提出並已被採納的修正是：把最初「集合處 → 途中接應標記 → 高地通道」改為「街口 → 已勘查通道 → 高地接應處」，避免額外創造接應站，或混用後來失效的原集合點。另要求所有未完成提示只描述核對缺口，不把未經指定點的路線宣判為死亡風險。
