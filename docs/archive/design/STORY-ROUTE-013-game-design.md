## 推薦：在已勘查簡圖上標路

玩家替角色**確認如何前往目的地**：從起點連接上下左右相鄰的可走格，經過指定地標，再到目的地。線條是紙面筆跡，街道、山坡與障礙固定；完成後才由劇情描述角色實際行動。不把拼圖畫成玩家搬動街道，也不把每格視為等長的真實地理。

| 方式 | 優點 | 風險與適用範圍 | 判斷 |
| --- | --- | --- | --- |
| 連接鄰格 | 點選即可，能直觀看見起點、途經地標與目的地；錯了可退筆。 | 須清楚說明是在規劃；不要逼玩家找唯一或最短路線。 | **首選**。小型、靜態、無限時。 |
| 旋轉路塊 | 操作具象，適合機關／管線組裝。 | 若畫成真實街道，旋轉會產生改造城市的錯覺；也比本次輕量需求多一層規則。 | 這輪不採用。以後若是可旋轉的實體機關才另議。 |
| 自由尋路／移動角色 | 有探索感，能直接呈現抵達。 | 需要鏡頭、碰撞、移動距離、遭遇與回頭邏輯；容易把敘事接點擴成另一種遊戲。 | 不作本次試點。 |

## 首選試點與敘事對齊

**T1-step-03 的既有 `evac`「整理已勘查的撤離簡圖」**最適合。它發生在暮鐘提前啟動之前，角色已有勘查資料；接著鐘響、隊伍再依已確認路線改向高地，因果自然。

劇情 agent 指出，既有圖塊包含街口、通道、高地、接應處，因此本案採 **街口 → 已勘查通道 → 高地接應處**。接應點就是終點，不新增途中接應站，也不把之後失效的原集合點設為必經。

- 未來實作應**取代或延伸同一次 `evac` 整理**，不是在 012 的拼圖後再加第二道題。先等 012 凍結，由產品另定基線、允許檔案與接線方式；本文件不覆蓋 012。
- 完成文字候選：「從街口經勘查通道，可接上高地的備用接應位置。」這只確認簡圖連通，不保證永久安全，也不能預測夜域。
- T2／T3 是最後幾步與數秒救援，不插入棋盤打斷動作。
- S3 維持六個完整回合的牽制戰與其後落柵撤離，不另加逃跑路線門檻。
- E3 維持組裝、破鎖、追兵戰、逃出的順序。
- P4 暫不插入父女坦白／分離的情緒段；若日後需要，可另議磷等待未果後讀筆記的轉場。
- C7 若擴充，須在既有 `help/direct` 決定之後呈現不同路線；不得把玩家畫得好壞改寫成是否幫忙，也不得取消兩條路合流。

## 可驗證的 5×5 示例

這是**示意資料，不是新正史城圖**。欄 A–E 由左到右；列 1–5 由上到下。只允許正交相鄰，不走斜線、不跨格、不穿障礙，同一路線不重複格子。

| 列／欄 | A | B | C | D | E |
| --- | --- | --- | --- | --- | --- |
| 1 | 可走 | 障礙 | 可走 | 障礙 | **終點：高地接應處** |
| 2 | 可走 | 障礙 | 可走 | 障礙 | 可走 |
| 3 | 可走 | 可走 | **必經：已勘查通道** | 可走 | 可走 |
| 4 | 可走 | 障礙 | 可走 | 障礙 | 可走 |
| 5 | **起點：街口** | 可走 | 可走 | 可走 | 可走 |

固定資料：起點 `A5`、必經 `C3`、終點／接應點 `E1`；障礙集合 `{B1,B2,B4,D1,D2,D4}`。障礙只表示簡圖中不可通行的地段；不自行新增倒塌、死亡等劇情事實。

開始前明示：「本次核對的是隊員已勘查、經指定通道的備用路線。」C3 一開始就以地標與任務文字標出，不是到終點才揭露的隱藏條件。表中「可走」只表示能在簡圖上相連，不代表任何路線都經過安全確認；漏過 C3 不能被描述成會死人或必然不安全。

合法例一（8 段）：`A5 → A4 → A3 → B3 → C3 → D3 → E3 → E2 → E1`。

合法例二（8 段）：`A5 → B5 → C5 → C4 → C3 → D3 → E3 → E2 → E1`。

可連到終點但尚未完成任務的例子：`A5 → B5 → C5 → D5 → E5 → E4 → E3 → E2 → E1`。因缺少 `C3`，回饋為「這條線還沒經過已勘查通道。」保留路線，讓玩家撤回修改；不觸發追兵、傷亡或時間懲罰。

**不要求最短路線**，符合連通與地標條件即可。沒有星等、隱藏評分、限時、隨機封路或永久獎勵。

## 互動與狀態契約候選

初始路線為 `[A5]`。主要操作是點格子；拖曳只是可選捷徑，不能成為唯一方法。

| 操作 | 契約 |
| --- | --- |
| 延伸 | 點目前尾端相鄰的可走格才加入；跨格／斜線／障礙不改路線，短句說明原因。拖曳快速跨過多格時也不能直接跳接或穿牆。 |
| 撤回 | 「撤回一步」移除末格，最少保留起點。點已畫過的格子，退回到那一格；不視為新增迴圈。 |
| 重設 | 清線回 `[A5]`，不關閉場景；提示不消耗資源。 |
| 完成判定 | 尾端為 E1、已經過 C3、每段相鄰、無障礙及重複格，才顯示「路線已接通」並啟用「確認路線」。到終點不自動跳劇情。 |
| 提示 | 指出任務未滿足項或一個可行的下一格；若已進死巷，提示撤回到可延伸的分岔。使用固定地圖與目前路線求解，不讀未來劇情、不加 RNG，不自動代畫整條線。 |
| 手機 | 5×5 全圖與主要按鈕盡量同屏；320 px 寬時，每格操作區至少 44×44 px。點按即可完成；多指、pointercancel 取消當次未完成手勢，回到手勢前草稿。轉向保留已確認的草稿段。 |
| 鍵盤／讀屏 | 方向鍵移動格子焦點，Enter／Space 執行與點按相同操作；撤回、重設、提示、確認均可 Tab 到達。格子名稱讀出座標、地標、障礙／已連接／可延伸狀態，不只報顏色；Escape 回到故事場景但不標完成。 |
| 關閉與重開 | 同一次節點 session 內可保留草稿供重開；離開節點或重新載入不要求持久化草稿。取消不前進、不存檔、不發獎。實作須與當時 campaign 契約對齊，不新增獨立存檔鍵。 |

候選暫態資料：`{sessionId,nodeId,puzzleId,phase,path,focusCell,hint}`。`phase` 為 `editing/ready/confirmed/closed`；地圖與條件是固定配置。`ready` 仍可撤回／重設；只有按「確認路線」且重新驗證成功，才進 `confirmed`。依既有拼圖介面交付成功**一次**，由 campaign 推進下一段；`closed` 或過期 session 的回呼必須失效。

成功只代表此互動完成，不等於 T1 整節已收錄。後文仍按現有規則讀完，只有既有收錄程序能保存節點完成。沒有新獎勵、傷害、戰鬥狀態或 AI 變更。若資料錯誤導致無解，顯示可返回的錯誤，不偽造成功、不讓玩家卡死在遮罩。

## 設計資料驗證與未執行驗收

2026-09-25 以一次性 Python、`collections.deque` 廣度枚舉從 A5 到 E1 的所有**不重複格子**正交路徑；到 E1 即停止延伸，再按是否含 C3 分類。執行結果：19 格可走、6 格障礙、3 條符合必經點的路徑、1 條漏過必經點的路徑、最短合法長度 8 段。上述合法例一及不合格例均以 assertion 核對。因此這份固定示例不是死局；**這只驗證設計資料，不是 UI／runtime 測試通過，也不是難度已驗證**。

驗證方法：佇列初值 `[[A5]]`；逐條取出 path，尾端為 E1 即分類，否則枚舉上下左右、界內、非障礙且不在 path 中的相鄰格，加入新 path。枚舉完畢核對合法集合非空、最短長度為 8、指定兩類示例確實在對應集合。未寫入測試腳本或程式碼。

未來試作驗收至少包含：兩條不同合法路線都可完成；漏必經、斜線、跳格、障礙、迴圈的正確拒絕；撤回／重設／提示；手機點按與鍵盤；拖曳取消、多指、轉向；反覆確認只回呼一次；取消不推故事；舊 session 回呼不影響新節點；T1 後續鐘響與收錄順序不變。上述功能案例本輪執行 **0 項**。
