## 設計結論

採「雙人相向構圖＋單一緊湊對話欄＋情境操作」，以目前的背景、透明人物與道具繼續組合。核心是讓玩家知道**誰在對誰說話、輪到誰回應、手上的線索此刻能做什麼**。

- 雙人站位在一段交談中保持不變；左側朝內看右方、右側朝內看左方，說話時只改姓名標記、表情或輕微亮度。不按每句台詞交換左右，不靠兩張正面圖冒充對視。
- 台詞在底部同一閱讀位置顯示，姓名／聲源與人物上的標記相呼應。對話長度自適應；長句、文字放大可增高，不能硬切成固定兩行。
- 普通閱讀、做出選擇、操作物件使用不同的互動方式。只有原本具選擇的步驟顯示選項，不給每句話硬加兩個同結果按鈕。
- 小任務的精細度優先來自「對象、依據、具體操作、可见結果」，不是增加點擊次數或倒數。

這些是 Nightfall Duel 的設計決策，不聲稱任一競品完整採用相同方案。

## 競品：已核實的做法與可借鑑之處

### Detroit: Become Human：調查如何影響交談

官方操作手冊將掃描、可操作物、分析、對話選項分開；部分選項與動作有時限。官方試玩介紹指出，探索可開啟後續對話或行動。這支持「找到線索後，交談出現新依據」的設計，但不代表所有對話都要限時。[操作手冊](https://playstation-doc.net/j/detroit/action1.html)、[官方試玩介紹](https://blog.playstation.com/archive/2018/04/23/7-things-youll-notice-in-your-first-30-minutes-of-detroit-become-human/)

實際查看手冊的選项截圖：角色占主要畫面，短選項放在人物附近，沒有覆蓋半幅畫面的長文面板。它依靠3D人物、前後景與鏡頭安排維持交談關係；截圖本身不能證明各場景都左右相向。[已檢視截圖](https://playstation-doc.net/j/detroit/img/img_action1_ss05.jpg)

本作應借鑑：先讓玩家看清情境，再給明確的回應意圖；任務提示靠近操作對象。保留目前無倒數的阅读與尋物，短語選項旁可補一句完整意圖，避免玩家猜按鈕實際會做什麼。固定劇情不顯示不存在的分支圖。

### Ace Attorney／逆轉檢事：讓物品成為交談的一部分

Capcom官方教學將 Talk、Examine、Move、Present 分開，說明對人出示證據可以得到更多資訊。《逆轉檢事》另有組合已取得資訊的 Logic 操作。這是將探索接回對話的可參考結構。[官方操作教學](https://news.capcomusa.com/lets/browse/ace-attorney-101-with-phoenix-wright-and-maya-fey)、[官方Logic介紹](https://news.capcomusa.com/lets/browse/ace-attorney-investigations-miles-edgeworth-demo-is-unleashed)

《逆轉檢事合集》導演說明：可調查提示移到人物附近以減少視線移動；看過的物件有勾號，內容改變時勾號消失。已實際檢視官方截圖，人物附近的放大鏡氣泡與已查閱勾號可清楚辨識；這張圖呈現調查提示，不作面對面對話的證據。[導演開發紀錄](https://news.capcomusa.com/lets/browse/directors-testimony-behind-the-scenes)、[已檢視截圖](https://cdn.capcom-unity.com/2024/09/ss_07en.png)

本作應借鑑：物件詳情中提供有意義的「出示／核對」操作，並明確區分已看、已收、已核對。E2第二批文件尚未開放時不能收取；新狀態提示只能揭示當前可做的事，不能亮出後續答案。不是把所有探索都改成全場亮框。

素材節省也有直接參考：Capcom記錄將不同語言的文字圖片改為即時文字加共用空面板。本作繼續將文字、姓名、標記與背景原畫分離。[官方在地化與技術紀錄](https://news.capcomusa.com/lets/browse/localization-and-technology-or-how-over-a-decade-of-progress-affects-your-localization)

### OXENFREE／OXENFREE II：聲音來源與場景同時存在

原作官方說明對話決定影響故事與人物關係，收音機是與超自然現象互動的工具。續作導演介紹對講機，使玩家能主動聯絡不在畫面中的人物、取得資訊。[原作官方介紹](https://nightschoolstudio.com/oxenfree)、[續作導演介紹](https://blog.playstation.com/2023/04/19/get-your-walkie-talkie-ready-for-oxenfree-ii-lost-signals-launching-july-12/)

本作應借鑑：C9的聲源綁在紀錄器，人物留在現場聆聽；E1標明「暮晶殘響」，不把聲音配給磷的臉。面對面只適用在場的交談者。此研究沒有實玩OXENFREE或逐幀分析其對話動畫，不宣稱量測過氣泡時序、打斷窗口或觸控操作。

## 面對面場景規格

| 情境 | 構圖與說話者呈現 | 保護條件 |
| --- | --- | --- |
| 兩人在場交談 | 固定左右位置，身體可略轉、眼神朝向對方；顯示当句發言者姓名 | 必須實際檢查目光，不以position=left/right視為完成 |
| 三人以上交談 | 每個交談段落先指定說話者與受話者；其餘人留在穩定的背景位置或明示仍在場 | 不把cast第一人永遠當受話者，不因換句便讓角色反覆進出 |
| 關鍵事件插畫 | 保留原有構圖；同樣顯示當句姓名／聲源 | 不為湊雙立繪覆蓋事故、救援或舉槍的關鍵畫面 |
| 畫外音 | 名稱＋畫外音，畫內人物可保持聆聽 | 不高亮不相干人物、不臨時虛構NPC外貌 |
| 錄音／殘響 | 名稱＋來源，輕微標記紀錄器或暮晶 | 不添父親實體，不辨認未知女孩身份 |
| 旁白／任務 | 分別標旁白、調查、行動、拼圖等 | 沒有speaker時不把兩人都亮成正在說話 |

建議首批構圖樣本：S1朔／鳴者（溫和交流）、C5伊芙／凜（對峙）、C7多人輪流發言、C9紀錄器（非現場聲源）。以這四類驗證配置，才擴到所有節點。

手機390px仍保留左右兩張可辨識的半身，眼睛、臉部及故事關鍵道具在安全區。優先減少人物下半身與面板空白；不為容納兩人縮小文字。對話欄置於人物臉部以下。1440與390均需看實際組合，不能只驗DOM未溢出。

## 對話框互動規格

| 狀態 | 玩家操作 | 結果與防誤觸 |
| --- | --- | --- |
| 普通逐句閱讀 | 點「繼續」或按該按鈕的Enter／Space；可將純台詞區設為同等繼續操作 | 一次輸入只前進一句；選字、捲動、紀錄按鈕不觸發前進，長按不連跳 |
| 若未來加入逐字顯示 | 第一次操作顯示當句全文，下一次操作才下一句 | 此為候選，010現有全句顯示可繼續沿用；不強迫等動畫 |
| 劇情選擇 | C7保留原有兩個意圖，點選後以明確按鈕確認 | 閱讀「繼續」不能代替選擇，等待時不自選；不新增好感度或結局 |
| 調查／物件交接 | 操作當前物件或對象，詳情後選「收取／出示／核對」 | 對話區點擊不能跳過任務；完成後顯示結果，再由玩家繼續 |
| 回看 | 開啟已讀紀錄或上一段 | 只讀，不重做拼圖、交接、獎勵或回寫選擇 |

底部保留一個主要操作，故事紀錄與離開列為次要控制。姓名與來源是常駐辨識資訊；頁數、未完成離開提醒可降為次要，但儲存失敗與操作失敗仍要可見。至少44px操作區；200%文字、鍵盤、觸控捲動與減少動態需獨立驗證。

## 小任務如何變精細：候選及投入順序

以下是研究提出的新互動候選，未修改現有規則，也未將其當成已完成。

| 優先順序 | 節點與候選 | 玩家真正要做的事 | 完成後看得見的改變 |
| --- | --- | --- | --- |
| 先接上現有物件 | B2出示書籤 | 從已持有物件選書籤，交給朔辨認 | 書籤出現在交接位置，接回原有辨認台詞 |
| 再讓線索形成依據 | C4文件核對 | 選現有文件中的案號／日期／封存用語，交給對應知情角色核對 | 分別標出已核對內容，最後得出既有「命令早於任務」結論 |
| 保留成功來源 | E3武器拼圖 | 仍按原答案配對五件；清楚顯示用途、接合位置及組裝狀態 | 組裝後才蓄能；不增加任意順序以外的新零件依賴 |
| 補真正救援操作 | T2／T3 | 選救援對象與合法接應位置，依既有因果交接／撐盾／撤離 | 人物移到安全側、盾留在掩護位；不是只改按鈕文案 |

B2／C4候選不增添新證據或對凜的無罪判定；人物只能談論自己已知的部分。T2/T3的救援提案仍需要角色／道具素材與有狀態的互動模組，投入高於把既有物件接回對話。優先確認操作結果是否可見，再評估細節動畫。

正確參考：[T2／T3救援提案](../story-rescue-interaction-spec.md)、[28節點當前實際機制](../story-search-001.md)。目前E2/E3/C9尋物已完成；T2/T3尚是行動按鈕，不能把對話UI改版當成救援玩法完成。

美術agent已用view_image實際檢視以下九張；表中左右均指**圖片畫面方向**，不是角色解剖左右。這是單張素材判斷，尚非新版遊戲合成畫面驗收。

| eve、eve-armed | 朝畫面右 | 伊芙置左側可朝內；持槍方向與零件左右須保留 |
| shuo、shuo-young | 頭朝右；青年版眼神較朝觀眾 | 成年朔置左可先試；青年版不能僅看頭部角度判為明確對視 |
| gran | 朝畫面左 | 成年格蘭置右可先試；保留盾、肩部裝備與側袋關係 |
| gran-young | 近正面、略朝右 | 待實際雙人構圖檢查，不預設為清楚相向圖 |
| phosphor | 面略朝右，眼神偏觀眾左上 | 需依受話者位置檢查視線；不能直接宣稱有清楚右向對視 |

因此**第一個面對面樣本可用現有「伊芙左＋凜右」**，不必先生成新圖；「成年朔左＋格蘭右」也具備可沿用條件。C5現有cast本來就是伊芙在左、凜在右，若仍感覺不是對話，還要檢查人物間距、臉部裁切、當句受話者及字幕焦點，不能把問題全歸為素材朝向。磷與青年角色的視線較不明確，才列後續姿態候選。首批未檢視鳴者／父親／赫爾曼的實圖，不對其鏡像可行性下結論。

對話構圖需將「身份、外觀階段、當句發言、受話者、左右位置、原畫視線方向、可否鏡像」分開。預設禁止自動鏡像，經美術確認才允許；同一交談段落保持配對和位置。這是資料契約建議，未新增runtime欄位。

既有圖若是正面，水平翻轉仍是正面。凜右手灼傷／繃帶、持槍方向、肩帶、盾與劍的左右關係必須保留；不能只把圖翻過去算符合要求。需要新圖時只補被證實缺少的相向姿態，沿用背景與其餘人物；先以一對角色驗證，不先量產全部職業×表情×方向。

素材另派工前需確定最大顯示區及張數。若首批確需兩張透明半身，建議runtime各以768×1152以內、≤300KiB為目標，合計≤600KiB；必須低於現行actor上限並維持完整alpha，詳細尺寸依構圖定案。原稿、參考與來源另存；本研究新增runtime為0 bytes，尚未生成或壓縮，預算不是已實現成本。

STORY-DIALOGUE-010產品已確認仍持有campaign／stage／performance／puzzles／HTML等來源，011不寫入。010目前負責薄字幕、身份／聲源及四拼圖回饋；本研究已同步「雙人相向與穩定對話對象」需求。更深的出示／核對／救援互動須有独立工單、修改前基線、單一寫入者與工程複審。

## 驗收與研究界線

- 研究：已讀三組競品官方介紹／開發者紀錄；直接在瀏覽器檢視Detroit官方選項圖與逆轉檢事官方調查提示圖。沒有購買／安裝／實玩競品，沒有把宣傳圖當性能測試。
- 美術：只讀agent已檢視九張主角透明人物，實圖判斷已列於共用素材段；不以檔名或CSS推測可鏡像性。未看其他NPC，不把素材檢視當成遊戲合成圖驗收。
- 後續實作：S1、C5、C7、C9在1440／390、200%文字、鍵盤與觸控檢查眼神相向、人物穩定、姓名與聲源一致、長文不裁切、單次推進、任務不可跳過、回看無副作用。
- 因果：赫爾曼死訊後不回到現場；父親錄音不證明人在場／活著；未知殘響不配磷肖像；凜右手不換側；C5/C6不變成伊芙已原諒。
