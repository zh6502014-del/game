# UI-CLARITY-009｜美術／UI 診斷與建議

日期：2026-09-24。範圍：目前故事暮晶戰鬥。狀態：**設計方案已交接，未實作、未驗收**。

已實際查看使用者第 8 回合截圖（赫爾曼博士對凜，原檔 2830×1440；工具縮放顯示），並讀取 `story-energy-ui.js`、`story-energy-ui.css`、[角色規範](../../agents/ART-UI.md)、[RESEARCH-008](../research/RESEARCH-008.md) 與現行素材預算。本輪不修改遊戲、不產生圖片、不做外部研究。尺寸規劃是靜態計算，並非已完成的瀏覽器驗收。

## 結論

問題主要是**同一件事被拆在多處、角色卡的附屬標籤互相搶焦點**。戰場有大量空白，但生命、護盾、攻擊、額度、職業和名字擠在不同外緣。只刪掉幾個標籤或縮小字體不會解決。

推薦一個整體方案：**緊湊雙列角色陣列＋卡底固定資訊座＋單一底部操作區**。保留敵上我下、主角置中、角色拖曳普攻與全隊常駐技能牌；去除右側長欄，把支出資源、技能與提交操作放在同一視線範圍。

這是故事戰鬥專用方案；不把其結束回合、暮晶或橫向陣列套入自由決鬥。

## 截圖的七個凌亂來源與程式接點

| 問題 | 截圖觀察／程式證據 | 修正方向 |
| --- | --- | --- |
| 1. 額度牌貼在五官上 | `.seb-allowances` 絕對定位 `top:16px`；小橫屏縮成 9px。兩個「普攻／招式已用或未用」牌直接覆蓋頭部。`unitCard()` 每人都產生此列。 | 放進資訊座的單一額度列；文字為主、無厚框，肖像不承載數值或額度。 |
| 2. 三個數值沒有共同讀取順序 | `.seb-stat-badges` 將攻／血放在底部左右外凸；`.seb-shield` 位於右側 `top:43%`。圓形與不同比例盾章分散。 | 固定為「生命、護盾、攻擊」同一基線、同款徽章底材、相同間距。數字與圖示語意不同，結構一致。 |
| 3. 身分、姓名、職業、狀態各自漂浮 | `.seb-unit-crown` 浮在頂端；姓名底條；`.seb-status-strip` 固定 22px 且不換行。`unitCard()` 有狀態時不產生職業，資訊會被替換。 | 名稱／身分／職業成穩定識別組；狀態永遠獨立，不取代職業。多狀態可以增高。 |
| 4. 資源與相關操作離得很遠 | 敵方暮晶浮在戰場左上；我方暮晶、選中者、普攻、結束回合垂直散在 `.seb-action-rail`；技能牌在另一個 `.seb-hand`。 | 敵方資源在敵列標頭；我方資源併入底部技能操作區，普攻按鈕直接標出目前角色。 |
| 5. 空間很大，角色資訊仍很擠 | `.seb-theatre` 固定分出 142px 右欄；`.seb-field` 兩列使用等分剩餘高度；`.seb-roster` 三等分、單人只佔中央格。卡最大 170px，但空白不承擔資訊分組。 | 戰場橫向統一，角色列由卡片實際高度決定並居中；單人與三人共用槽位尺度，不把單人卡拉成巨幅。 |
| 6. 中線訊息與底部兩側教學打斷視線 | `.seb-battle-message` 佔兩列中央；`.seb-hand-label` 在技能左邊、`.seb-hand-note` 在右邊；同時還有 `.seb-rail-note`。 | 常規最新事件移至操作區上緣單行；選目標時才切成操作提示＋取消。固定規則留說明／詳情，不在三處重複常駐。 |
| 7. 裝飾與小字一起增加負擔 | `.seb-field` 外框、內陰影多重框、`::before` 內框、中心線，加上獨立右欄框。短橫屏的額度、狀態、身分降到 8px；牌名 10px。 | 保留一層桌邊和一套角色框；以留白、同一底材與對齊分組。輔助資訊以至少 12px 為目標，主要文字 14px；放不下用布局切換／捲動，不能繼續縮字。 |

對照位置：CSS 約 25–59 行（戰場／角色）、64–102 行（訊息／操作／技能）、161–200 行（短橫屏）；JS `unitCard()`、`roster()`、`skillCard()`、`render()`。以上行號是本輪讀取時的位置。

## 推薦的整體資訊層級

第一眼：當前階段、我方可行動者、敵我生命及關鍵狀態。第二眼：技能費用、我方暮晶、對應角色和操作對象。第三層：詳細被動、完整效果、固定規則及歷史。

```text
頂列：遭遇名稱（次要）       第 8 回合・我方行動       說明／戰報／離開
      目標摘要                              敵方暮晶 0/3
                       敵方角色陣列
                 （中間保留攻擊路徑）
                       我方角色陣列
操作提示：目前角色／目標或最新事件                       取消（需要時）
底區：全隊暮晶 1/3    [全隊常駐技能牌]    [凜・普攻] [結束回合]
```

- 敵方暮晶放在敵列起點的標頭區，不能浮進某張敵人卡而被誤認為該人私有資源。
- 中間戰場維持動作空間，但不常駐膠囊事件文字；圖像背景保持低對比。
- 1v1 使用中央槽位；3v3 保留主角居中，夥伴與敵人穩定排列。隊伍增減不重新改變角色卡內資訊順序。
- 所有操作集中底部，但敵我數值仍放在各自角色上，不能把重要戰鬥資訊都收進底部詳情。
- 頂列品牌字、遭遇大標題降為次要；小螢幕可以省略純裝飾品牌字。目標、回合及階段仍可讀，不能移掉實際勝敗條件。

## 角色元件：肖像＋資訊座＋狀態

桌面保留拱形肖像。由上往下：

1. **肖像**：只呈現人物及必要的選取／合法目標輪廓；不放額度、盾值或橫跨臉部的提示。
2. **識別列**：名稱為主要文字；「主角／夥伴」為小字或同套紋章附文字，與名稱同組。敵方身分以敵列標頭表達，不必每人一頂大膠囊。職業固定在名稱下或旁邊，不能因狀態出現而消失。
3. **三值列**：生命 → 護盾 → 攻擊，順序固定。使用同款古金斜角徽章、等寬數字；HP 可略高權重，盾與攻不再浮到卡片外側。0 仍顯示，不用進度條。現有最大生命維持可在詳情讀取，不另增窄卡分母。
4. **額度列**：普攻／招式各一個簡潔記號＋「未用／已用」，無厚框。這列描述本回合額度，**不是合法性保證**。
5. **狀態列**：在資訊座後獨立流式換行，圖示＋短名稱／次數；沒有狀態時不塞職業或「無」湊高度。若需要對齊可保留一行最小空間，多於一行允許增高。

「未用」與「可用」必須分清：

- 暮晶不足且 `skillUsed=false`：額度仍顯示「招式未用」，技能牌顯示「暮晶不足」或「缺 1 暮晶」，不能用可施放亮框。
- 暈眩／效果尚在：額度與限制並存；限制的完整原因在點選／詳情可取得。
- 可提交亮框依 `legalActions` 及播放階段決定；不能只看 `!attacked` 或 `!skillUsed`。
- 敵方額度只描述公開狀態，不假裝預告 AI 接下來會施放什麼。共用暮晶不是每人各有三點。

資訊按鈕保持可見、可聚焦、有至少 44px 操作區；不要沿用只在 hover 才出現且透明的 `.seb-unit-info` 作為觸控唯一入口。它應是角色元件內一個穩定操作位置，不能覆蓋三徽章、擋住拖曳或把整個姓名當作無提示暗門。

## 底部操作區

合併 `.seb-action-rail` 與 `.seb-hand` 的**呈現布局**，保留既有行動與輸入契約：

| 區域 | 常駐內容 | 展開或選取時內容 |
| --- | --- | --- |
| 左：團隊暮晶 | 小型共用暮晶符號、清楚的數字 `1 / 3`、團隊標籤 | 可查看補充規則；不將「首回合／累積上限」常駐在另一側 |
| 中：全隊技能 | 各人 7:10 技能牌、費用、短名／技能名；依角色順序排列 | 完整效果、使用限制及所有者詳情；不可用仍能讀取 |
| 右：一般操作 | 目前角色標在「凜・普攻」按鈕，最右為結束回合 | 待指定時顯示來源／動作／目標與可見取消；不能只剩拖曳 |
| 操作區上緣 | 一條最近事件或當前任務提示 | 詳細事件進既有戰報，訊息可換行而非遮掉按鈕 |

不刪除點選、鍵盤、資訊按鈕、Escape、長按預覽及拖曳。普攻替代按鈕仍是選擇普攻後再選目標，不改成一按就替玩家自動找敵人。結束回合保持獨立而固定在操作區右端，44px 以上，不能混成卡片或挨著詳情小按鈕。已用或無合法行動也保留查看原因的途徑。

技能卡缺費用時避免現在遮住中央插畫的大橫條；將簡短原因放在卡名／底部資訊帶，若小卡放不下則選取後在共用操作提示說明。卡名、費用與所有者不可全藏；資訊按鈕的 hit area 不能與鄰牌或費用徽章互相截取。

## 1v1、3v3 與短橫屏的可行尺寸

以下為**待實作驗證的預算**，不是宣稱所有組合已經同屏。

### 一般桌面／較高橫向畫面

- 隊伍列建議總寬約 600～680px，單張角色約 176～200px 寬；兩列卡片之間保留約 24px 以上動作間隔，避免使用兩個無上限的等分高格子。
- 大肖像＋資訊座的角色卡自然增高，整體可落在約 210～250px 高；一人仍使用相同尺度的中央位置。
- 底部操作區約 140～160px，自有內容決定高度。技能牌維持 7:10，不拉長填滿整欄。

### 667×375 的 3v3

直接沿用高直式卡會失敗：即使一張只有 160px，高度兩列就需 320px，再加頂列與操作列已超過 375px。因此推薦同一元件的**短高版**，不靠縮至 8px 文字：

- 可用寬度約 651px（左右各 8px）。三張約 200px 寬，兩間距各 12px，共 624px，可居中容納。
- 每張目標約 96～104px 起：小肖像置上方左側，姓名／職業／額度在上方右側；三數值同一底線跨整張，狀態獨立在後。肖像仍不承載 badge。
- 高度示意：頂列 44px＋角色兩列約 208px＋操作區 96px＋外距／列距約 27px＝375px。這只適用一般短名稱、狀態至多一行及正常文字尺寸；名稱換行、多狀態、瀏海安全區增加時必須讓布局增高／捲動。
- 技能牌約 67×96px，三張含間距約 217px。保留費用、至少 12px 的技能名／短所有者；完整說明在詳情。普攻／結束回合可以在操作區右側上下排列，各至少 44px，結束回合仍位於右端。
- 暮晶改為緊湊 inline 數值＋小符號，不用三顆大型寶石佔一整行。三顆符號若保留，必須是與數字相同資訊的裝飾，不新增操作意義。
- 長姓名、兩位小數及多狀態不能以 clip／ellipsis／縮字解決；先改數值欄寬與自然高度，需要時進入可捲動布局。

### 文字放大 200%

不承諾 667×375、3v3、全部狀態、200% 文字仍同屏。此時保留資訊完整比保持固定舞台更重要：

- 卡片與列高改為 auto／min-content；三徽章必要時換行，但順序不變；所有狀態和職業仍可取得。
- 優先讓戰場成單一垂直捲動區；操作區可增高為兩行，結束回合在其末行右側。若剩餘可視高度太少，整個 shell 轉單軸垂直捲動，不用固定 footer 蓋住人物資訊。
- 現行 overlay 的 `overflow:hidden`、`touch-action:none` 與到處 `min-height:0` 不能不加區分地保留。後續實作需讓可捲區能 pan-y，drag source 保留單指追蹤，避免同手勢被同時當捲動與出招。
- Tab 必須把真正取得焦點的角色／技能／操作捲入可視區；不能一直 `preventScroll:true` 導致焦點在畫面外。操作清理、主指取消契約與進度保留仍不變。

## 視覺語言與不採用方案

只保留一層低對比桌緣、角色主輪廓與重要互動亮框。資訊座以墨綠底材＋細分隔線分區；三數值徽章使用同一斜角底型，職業色只作局部識別。取消、已用、不可用不各畫一套厚金框。狀態以現有 SVG 語意、文字及有限描邊呈現，選取不只靠顏色。

新增圖片預算：**0 張**。沿用現有原畫、共用 SVG、框材與背景；不生成大底圖來處理布局。相同角色不因短高版另生肖像。

| 不採用方案 | 原因 |
| --- | --- |
| 把所有數值和狀態收進詳情 | 每次選目標都需要額外讀取，降低戰鬥判斷速度；只能收長規則，不能收掉 HP、盾、攻和關鍵狀態 |
| 只刪職業／額度／敵方暮晶 | 遮蔽原有決策資訊，未處理分組；職業應固定，額度需與可用性區分 |
| 只縮卡／縮字以維持全尺寸同屏 | 已存在 8px 字級問題，200% 文字與多狀態會更脆弱 |
| 保留大右欄，只再加底部資源 | 形成重複資源與第二個操作中心，視線更分散 |
| 改成巨大單張角色、1v1 專版 | 3v3 時必須重學版面與縮回小卡；同一槽位元件比較穩定 |
| 每個元素套一個金框，或加亮背景特效 | 古金權重失去層級，邊框搶走數字與角色表情；增加美術容量無法修正資訊結構 |

## 第一批可執行項目與驗收

由產品另開實作範圍後才修改 runtime；目前只是建議順序。先保存基線，指定單一 `story-energy-ui.js/css` 寫入者；不要多人並寫。

1. **角色資訊重組**：將姓名、身分、職業、三值、兩項額度及狀態放進同一可重排元件；停止遮臉、外凸和職業替換。保留 `data-seb-unit`、focus key、目標及事件落點契約。
2. **操作區合併**：移除右側長欄布局，把團隊暮晶／技能／普攻／結束回合集中到底部；普通事件和指向提示分清。保持 act／endTurn 呼叫與 keyboard／pointer 行為。
3. **桌面與短高版一起驗證**：不是桌面做好後才用媒體查詢全面縮小。正常字級看 1440×900、1280×720、844×390、667×375；每種至少 1v1、1v3、3v1、3v3。
4. **擴大文字／狀態壓力**：長姓名、全類型狀態組合、0／小數數值、三技能不同費用、暮晶不足但技能未用、已用／暈眩／效果尚在；測 200% 文字。不得角色相疊、數值裁切、職業消失或用橫向整頁溢出逃避。
5. **操作與因果回歸**：點選普攻、拖角色、拖技能、自身技能、資訊按鈕、鍵盤、Escape、主指 pointercancel、次指忽略後主指合法提交一次、失焦／旋轉取消、減少動態、素材失敗、演出中輸入鎖與回故事。frames 結束數值仍等於引擎 after，不新增傷害／費用／AI／RNG 計算。
6. **工程／產品驗收**：逐比對畫面與 hit area、每種姿態的資訊完整性、render 的 focus 恢復與可捲區；FX 的命中座標在卡版式改動後重新核對。最後更新資源版本與適用既有回歸。

驗收需附桌面與 667×375 對照圖、200% 捲動模式圖、輸入路徑結果與未驗證項目。真機表現及跨瀏覽器不能以靜態規劃或 viewport 測試代替。
