# 美術、UI agent 交接

更新日期：2026-09-23。角色識別：`art_ui`。專案：Nightfall Duel／夜幕決鬥。

本代理由產品 agent 持續指派工作；使用者只需向產品 agent 提出需求，不必到其他對話重新說明。本文件是既有產品的維護契約，不是重新設計提案。本次僅建立此文件，未修改遊戲程式、素材、入口或快取版本，也未執行瀏覽器測試。

## 角色職責與修改權限

- 維護古金 × 墨綠暗黑奇幻的視覺一致性：角色、卡面、牌背、圖示、PNG 邊框、靜態場景與故事插畫的視覺規格。
- 負責選角、HUD、手牌、放置區、詳情、彈窗、結算及故事介面的資訊層級、裁切、響應式排版、可讀性與可操作狀態。
- 提供素材尺寸、透明度、命名、映射、生成來源與備援規格；協助核對實際畫面、DOM 邊界、鍵盤焦點及文字放大。
- 先接受產品指定的檔案範圍，再實作。檔案列在本文件只表示維護關聯，並不代表可自行修改。
- `game.js`、所有 HTML 入口、共用 CSS、載入順序與快取版本均屬共享整合範圍，不得擅改。需要更動時，向產品提交具體 selector／介面／檔案清單及原因，由產品協調修改者與整合順序；同一共用檔案不得多人同時寫入。
- 本次任務的唯一可寫檔案為 `docs/agents/ART-UI.md`；其他範圍保持唯讀。

## 後續素材尺寸與容量（ART-BUDGET-007）

所有新素材必遵守 [美術素材尺寸與容量規範](../../art-asset-budget.md)。這是後續派工的持續要求，覆蓋上方 TEAM 建置紀錄。

- 先量實際用途，再定生成張數／尺寸與 runtime 上限。卡面通常最多 512×768／250 KiB，硬幣 256×256／80 KiB，背景最多 1920×1080／600 KiB；其他用途以規範及 JSON 為準。上限不是生成目標，不把小圖放大。
- 不預設 4K 或多候選；沿用共用素材與分層場景。內建 imagegen 不能保證指定像素，生成後量實際結果，不為縮圖反覆生成，也不擅切 CLI／模型。
- 原稿只保留一份，新遊戲載入檔採適當壓縮；保留透明度、比例與生成紀錄。不要直接交付多 MB 的原始 PNG 給小元件，也不擅自刪除現有版本。
- 交付必跑 `python3 scripts/check-art-budget.py --strict <新／改 runtime 檔案>`，附每張尺寸／bytes、原稿與 runtime 總增量、實際縮放品質證據。超標回產品解決，不自行改預算使檢查通過。

## 明確不負責項目

- 不決定產品優先級、驗收範圍、發布時間或跨角色衝突的取捨。
- 不調整傷害、AI、抽牌、RNG、合法出牌、回合推進、勝負、解鎖條件或存檔結構；不把顯示格式回寫遊戲狀態。
- 不自行撰改世界觀、人物關係、劇情分支或解謎答案；素材與文案疑義交產品及劇情 agent。
- 不主導動畫時間軸、粒子、戰鬥回饋或音效資源；與特效、音效 agent 協作其視覺落點及遮擋界線。
- 不以「整理重複樣式」為由擴大至未指派的架構或功能重構；需要重構 cascade 時由產品排入工單並保留畫面與互動回歸。不以過往截圖當成本輪通過證據。

## 既有古金 × 墨綠暗黑奇幻規範

- 暗墨綠琺瑯、古金雕刻、低對比皮革與金屬鑲邊為共用材質。現行色值參考：`--table-gold:#bea16c`、`--table-ink:#0b2020`、HUD 底色 `#112925`、PNG 邊框 `#a78d58`、主文字 `#f1e0b9`。這些是現況參考，不是要求一次抽換全站 token。
- 原創角色與古堡原畫為主，職業色限於紋章、狀態與局部光影。避免高飽和色整片搶走生命、牌面和操作焦點。
- 玩家在左、決鬥在中央、對手在右；手機仍保留左右對戰。手牌、放置牌保持相同視覺比例，雙方 HUD 等高並容許內容自然長高。
- 長敘述靠左、名稱置中、數值使用等寬數字；正文以 14px、輔助資訊以 12px、主要操作區以 44px 為既有基準。勿以縮字、裁切名稱或藏數字解決空間不足。
- 裝飾不承載唯一的遊戲資訊；狀態要有圖示與文字，選取、停用、焦點不僅靠色差。裝飾層使用 `pointer-events:none`。
- 不加入多餘的 YOUR HAND、OPPONENT、END TURN、對手手牌張數或重複 VS 標籤。回合由系統推進，不能新增「結束回合」按鈕。
- 既有 SVG 圖示由 `icon-registry.js` 共用，24×24 viewBox、主線寬 1.75、斜角幾何；新增圖示先比對既有系統，不另起一套風格。

## PNG 九宮格與不透明翻牌保護

| 邊框 | 切線 | 現行用途 | 顯示原則 |
| --- | --- | --- | --- |
| `hero.png` | 224px | 選角、肖像、手牌、牌背、翻牌、首頁、決鬥台、結算 | 角尺寸約 10–32px，依元件與窄畫面調整 |
| `panel.png` | 208px | HUD、放置槽、操作列、彈窗、故事對話與收藏 | 主要顯示角約 14–22px |
| `thin.png` | 176px | 按鈕、狀態、生命裝飾、職業角標、外觀控制 | 主要顯示角約 8–10px |

1. 中央保持透明，`border-image` 不使用 `fill`；`border-image-repeat:repeat`，四角等寬高，不把整張圖拉伸成長框。圖片、文字與框線分層，PNG 失敗仍保留 CSS 實線。
2. 保留圓形音效鈕、VS 紋章、輪播點、細分隔線及資源條的既有形狀，不把所有元件硬套矩形框。切片腳本只裁切與提取，不重畫素材。
3. 未揭曉牌統一使用 `assets/cards/back-gold-v1.png`，所有職業、外觀、卡種相同。既有資料記載為 1060×1484、5:7、不透明 RGB PNG；以 `object-fit:cover` 等比例顯示，下方有不透明牌身。正常載入隱藏舊 SVG 封印，失敗再用備援，禁止透過牌背洩漏卡種。
4. 翻牌正反面均維持 `position:absolute`、100% 寬高、`opacity:1`；以父層 180° 旋轉與 `backface-visibility:hidden` 控制朝向。不可把牌背改回 `position:relative`，也不可重加透明度切面動畫。
5. `.card3d` 保留 `filter:none`、`overflow:visible`、`transform-style:preserve-3d`、`opacity:1`；陰影留在牌面。保留向外 0.7px 的兩面及 1.4px 紙芯側緣。不要把 `overflow:hidden` 套到 3D 容器或放置／翻牌區；只裁切插畫窗與需要裁切的手牌／牌背圖片。
6. 不擅改抬升／翻牌／落地 280／680／340ms 或回合等待機制。減少動態仍要有可讀的正面與結果；不要只檢查 opacity，必須看實際繪製、朝向與命中測試。

## HUD、數值與素材映射保護

- `hud.css` 將頭像、身分、資源、狀態拆成獨立區域。桌面左右鏡像，手機內容可換行；生命／護盾保留數字欄寬與 `tabular-nums`，裝飾裁切放在偽元素，不裁數字本身。
- `game.js` 的 `hudNumber` 只顯示最多兩位小數並去尾零，不改真實 HP／護盾。小數仍屬真實戰鬥資料；不得四捨五入回寫狀態，也不得用整數文字掩蓋小數。
- 八套頭像（四職業 × 基礎／origin）在 `game-art.js` 有獨立裁切；肖像只在 `.portrait-window` 內裁切。外觀圖失敗時回基礎原畫並恢復基礎裁切，再失敗才顯示職業紋章。
- `card-art.js` 定義三張基本卡、四張職業卡、劍氣與領域共九張映射，預設裁切為 `50% 28%`。`game-art.js` 套入手牌、放置／翻牌及詳情，讀取 `data-art`、`data-skin`、`data-owner`；改 DOM 前必須列明這些介面是否保持。
- 日夜背景與領域讀取實際狀態快照；任一方夜襲則為夜景，任一方領域啟用則保留領域底紋。美術不能用裝飾事件自行切換遊戲狀態。特效只消費結果，不重新抽 RNG 或計算傷害。

## 現況與待查風險

**本次已確認（靜態閱讀）**

- 三個主要入口最後均載入 `png-frames.css`，本機 CSS／JS 引用有 `?v=` 內容版本；現行 CSS 和 manifest 對應 hero 224／panel 208／thin 176、repeat 與透明中心。版本 hash 是否全數正確，本次未重跑檢查。
- HUD 分區、八套肖像裁切與逐級備援、九張卡面目錄、統一牌背及不透明翻牌結構均可在現行程式找到。`test-results/` 有 PNG 框、牌背、HUD、翻牌報告；這是既有檔案，不代表本輪執行。
