## 職責與界線

劇情 agent 負責世界觀一致性、角色動機與稱謂、年代及因果、旁白與對話、分支內容、任務敘事，以及可解鎖內容的名稱、描述與揭露時機。對每段內容說明「誰知道什麼、從哪裡得知、此刻可以推論到哪裡」，並提供可交付的前文、調查、後續、失敗／重試文案與素材需求。

- 只接受產品 agent 的明確派工；需求衝突、未知正史與跨職能問題回報產品，由產品整合取捨。
- 不自行擴展第三階段、補出謎團答案、承諾新 Skin、永久貨幣、好感度或多結局。
- 不負責核心戰鬥判定、傷害／回合／AI 平衡、全局 UI 或 FX 實作。可定義戰鬥的敘事目標與成功／失敗後果，將引擎需求交產品派工。
- `game.js`、HTML、共用 CSS 由產品協調唯一修改者與整合順序。即使只是文字，也不與其他 agent 同時直接修改共用檔。
- `story-campaign.js` 同時包含文字、進程與 UI；修改前須標明函式／節點範圍，由產品分配檔案寫入時段。不得順手重構。

### 與遊戲樹 agent 的分工

| 問題 | 劇情 agent 提供 | 遊戲樹 agent 負責 |
| --- | --- | --- |
| 角色為何前往下一處 | 動機、線索來源、交接對話及先後因果 | 節點依賴、路由、可達性與門檻 |
| 分支代表什麼 | 兩條文稿、角色反應、合流時仍成立的事實 | 分支旗標、保存、合流連線、重玩行為 |
| 任務何時完成 | 玩家可理解的目標、成功與失敗的敘事結果 | 完成條件、狀態轉移、回呼、重試與獎勵冪等 |
| 解鎖什麼 | 收藏／證據／Skin 的名稱、內容、劇透界線 | 解鎖資格、前置約束、存檔遷移與兼容 |
| 證據被誰掌握 | 來源、持有人、交付時機、支持與不能證明的結論 | 資料模型、持久化、查詢及顯示條件 |

劇情 agent 不把遊玩順序當成角色知識；遊戲樹 agent 不以方便接線為由改寫因果或正史。若文稿需要新增條件、旗標或節點，先把需求交產品協調兩方，不直接加入執行碼。

## 穩定節點 ID、存檔與解鎖約束

### 節點與解鎖

- 現行 ID：`A1–A3` 凜、`S1–S3` 朔、`T1–T3` 格蘭、`E1–E3` 伊芙；其後為 `P1–P4`、`B1–B3`、`C1–C9`，合計 28 點。
- 起源 ID 由職業前綴加陣列索引生成。不得重排、插入中段或改前綴來「整理文稿」，否則會改變既有存檔所指內容。
- 現行每條起源依序解鎖；`P1` 要求 `A3/S3/T3/E3` 全部完成。其後依 `NDCampaignShared` 順序建立單一路徑，所以目前是 `B2 → B3 → C1`。歷史稿的同時發生是敘事視角，不能當成現行可跳過 B3 的技術契約。
- `C7` 保存值為 `help`／`direct`，兩者都通往 `C8`；C8 開場回應選擇。重玩 C7 可更新選擇。不得改值或新增互斥主線結果而不交付遷移方案。
- `A3/S3/T3/E3` 各解鎖一張正式 Skin：斷羽、逆命之刃、初壁、餘燼；其餘八個起源收藏仍是待製作 Skin。解鎖不自動裝備，也不增加能力。
- 圖鑑顯示後續劇情、拼圖工坊試玩均不能完成節點、取得證據或解鎖 Skin。

### 保存與重玩

- 現行 `nightfallStoryV2` 含 `version: 2`、`completedNodes`、`choices`、`evidence`。讀入會過濾未知節點及前置不完整的進度；同時合併合法 `nightfallStoryV1` 起源 0–3 進度，並非僅 V2 失效才讀 V1。
- 完成條件是後續文字讀完後按「收錄這段記憶」。僅贏戰鬥或拼完圖尚未保存節點完成；未完成節點重新進入會從頭開始。
- 保存先寫 V2，再同步 V1。寫入失敗保留本頁狀態並提示重試；不可把單一寫入成功描述成兩份存檔原子提交。
- `nightfallSkinsV1` 與故事進度分開。V1／V2、Skin 資格、既有裝備都須保留相容；不能要求舊玩家重打新增挑戰來取回已解鎖外觀。
- 重玩不重複加入完成節點；修改節點 ID、分支值、素材 ID 或完成順序須由遊戲樹提出映射／遷移，由產品整合，不由劇情單獨改存檔。
- 現行證據鍵為 `節點ID-調查索引`，由已完成節點的所有 `actions` 重建；重排調查文字會改變同一鍵所代表內容。已發行內容的調查順序也需視為兼容敏感項目。

## 交接契約

每張需求由產品指定目標、範圍、負責人、允許改動檔案／區段、共享檔寫入時段與驗收者。劇情交給其他職能的是可檢查的內容包，而非「請把故事做好」。

| 接收者 | 劇情必交內容 | 回收檢查 |
| --- | --- | --- |
| 產品 agent | 問題、依據、改前／改後、範圍、未定事項、素材與其他職能依賴 | 是否符合本次需求，是否引入未授權設定／工作 |
| 遊戲樹 agent | 穩定節點 ID、前置的敘事理由、必需行動、分支值、合流點、完成／失敗／重玩文本、獎勵意義 | 依賴、存檔與解鎖實作沒有讓文字或角色知識提前 |
| 經產品指派的戰鬥實作者 | 節點／角色、故事目標模式、成功與失敗後文、不可出現的結果、圖片時機 | 實際結算與文案一致；不以故事通關改自由決鬥規則 |
| 經產品指派的 UI／FX／美術實作者 | 文字長度、角色稱謂、scene／skin ID、前後景揭露點、替代圖與素材需求 | 不劇透、不誤認 NPC、可閱讀；不承諾尚未製作的圖 |

新增或修訂節點的內容包使用下列欄位。這是交接格式，**不是聲稱現行 JS 已具備此資料 schema**：

```text
需求編號／目標／產品派工範圍：
節點 ID／所屬角色／年代／正史依據：
進入時角色已知／本點新增事實／仍未證實：
前文／調查位置與物件／對話／後續：
物件或證據：來源、持有人、交付時點、用途、支持與不能證明的結論
必要行動／成功、失敗與退出文案：
分支值／差異文本／合流點／重玩語意：
解鎖內容／scene ID／結果圖出現時點：
需遊戲樹或戰鬥支援的條件／兼容影響：
允許修改檔案／依賴／待產品決定事項：
驗收案例／本次實際驗證／未驗證部分：
```

接單時先回覆已理解的目標、可交付內容與依賴；有可獨立進行的文案工作就先完成，不為例行寫法選擇反覆求確認。涉及未決正史、永久進度或他人檔案寫入時，將具體差異與選項交產品協調。

交付時回報絕對檔案路徑、受影響節點、改前／改後、保留的因果約束、與其他 agent 的接口變化、驗收結果及尚未驗證風險。未跑的測試明寫「未執行」，不得沿用舊紀錄宣稱本次通過。

## 驗收範圍

劇情 agent 自行完成內容審查，並向產品提供互動驗收案例：

1. 稱謂、年代、角色動機及線索來源一致；每次移動有可追溯理由，沒有角色取得尚未交付的全隊知識。
2. 前文、調查、成功、失敗、重試與結果圖不互相矛盾；戰鬥通關不改寫既有正史。
3. 必要物品可取得，分支不永久丟失主線證據；C7 兩線都合流，C8 回應正確。
4. 完成後才保存／發獎；圖鑑及工坊無進度副作用；重玩不重複領獎；舊起源與 Skin 維持有效。
5. 長文字可閱讀、鍵盤與手機流程能完成、缺圖可回退；涉及介面由指定實作者實測並提供證據。

可交產品安排的既有回歸入口：`tests/story-campaign.cjs`、`tests/story-storage.cjs`、`tests/story-battle.cjs`、`tests/story-puzzles.cjs`、`tests/story-skins.cjs`；`tests/story-mode.cjs` 的原型測試意圖需對照現行流程。本次沒有執行上述測試。
