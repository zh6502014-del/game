本文件供產品派工及美術／UI、遊戲樹交接使用，遵循 [AGENTS.md](../../../AGENTS.md) 與 [分派流程](2026-09-25-README.md)。需求、範圍及整合由產品統一處理；角色文件不代表常駐代理服務。本輪 `TEAM-002` 僅依 2026-09-23 工作區唯讀盤點，未執行新驗收、未修改遊戲或測試檔案。

## 職責與非職責

**負責**：將已決定的戰鬥結果呈現為翻牌、攻擊軌跡、受擊、閃躲、護盾、灼傷、浮動數值、硬幣、日夜與技能環境；維護動畫取消、重入、防重播、減少動態模式；處理音訊素材、播放生命週期、音量、靜音與失敗備援。每項變更須有對應觸發情境與可檢查的結果。

**不負責**：決定命中／閃躲／反擊／夜襲結果、重新擲硬幣、修改傷害與護盾公式、卡牌合法性、AI、回合次序、故事或遊戲樹進度。不得為了動畫順暢而偷偷改變規則、刪除事件或縮小數值。角色原畫、卡框、字體、HUD 版型與按鈕設計由美術／UI agent 主責；本 agent 提供所需錨點與動態限制。

## 呈現規範

### 翻牌、剛體與不透明材質

- 卡片以連續 180° 旋轉呈現剛體翻面。抬升、翻面、落地維持目前 `280 / 680 / 340ms` 順序；音效在翻面開始時觸發。修改回合等待時間需產品與遊戲樹 agent 確認。
- 兩面固定為 `position:absolute`、覆蓋整張牌、`opacity:1`；可見面由父層旋轉及 `backface-visibility` 決定，不再用正反面透明度動畫交換。90° 時可只看見薄側緣，這不代表材質透明。
- 保留兩面向外 `translateZ(.7px)`、1.4px 紙芯與側緣。不得在 `.card3d` 父層加入使 3D 扁平化的 filter、裁切或透明度；陰影放在合適的卡面／獨立層。
- 高度採連續拋物線式變化；落地先到桌面零高度，再作小幅向上反彈，不穿桌、不縮放壓扁牌身。指標拖曳優先保持操作準確，不能套用追隨延遲。
- 驗證需檢查實際繪製／命中與 90° 前後影格；只看 computed opacity 不足以證明翻面正確。

### 攻擊、撞擊與浮字節奏

- 依雙方放置牌的實際 DOM 座標決定攻擊方向，從相向牌緣發射。軌跡先行，到接觸點才顯示命中、受擊及數值；目前飛行時間由距離推算，限制為 `110–210ms`。
- 目前每方事件依原陣列順序，以 `80 + index × 540ms` 發射；撞擊後留足浮字閱讀時間。不得為演出美觀而重新排序規則事件。現有完成時間依事件數計算，不應把歷史文件的「通常約 1.35–1.7 秒」當成所有回合的硬上限。
- 受擊採 `exp(-6t) × sin(3πt)` 阻尼回彈，從零位移出發、衰減回原位。爆擊放大動量與局部光效，不壓扁卡片。碎屑使用固定初速與 `y = v₀t + 360t²`，不呼叫遊戲 RNG。
- 閃躲在接觸前沿攻擊垂直方向移動，軌跡穿越原位置，不顯示命中火花或受擊震動。完全由護盾吸收時牌／護盾小幅讓位，HUD 不震動；碎屑向來襲方向散開。
- 灼傷使用局部熱光及既有事件數值，不加彈道、碰撞火花或機械撞擊。領域轉換呈現轉換／回復結果，不自行計算新傷害。
- 浮字直接使用事件的 `hp`、`shield` 正負值；`miss` 顯示閃避，零數值可顯示格擋或領域提示。保留圖示、文字、數值，不能只靠色彩傳達。多事件保持可讀，避免遮住手牌及必要操作。

### 日夜、技能層與硬幣

- `#nd-environment` 位於每回合重新渲染的 `#app` 之外，持續存在。任一方 `night` 為真便為夜景，雙方都解除才回白天；不能用最後顯示的硬幣字樣覆蓋雙方狀態。
- 硬幣僅展示既有判定，揭曉完成才同步真實日夜；目前背景交叉淡入為 700ms。硬幣保留雙面、薄側緣、獨立陰影及可讀結果文字。
- 六種技能環境為 `swordsman / tank / assassin / gunner / spirit / domain`；依玩家、AI 的順序各 300ms。免費護盾／領域使用既有獨立入口，不假裝消耗正常出牌。
- 技能瞬間光影位於背景與場地層，低於卡牌、HUD 及操作區，不攔截指標。技能結束只移除瞬間層，不能重設日夜；領域低強度刻紋由雙方 `domainActive` 控制。
- 背景圖失敗使用既有底色及頁面背景；素材失敗不得阻塞出牌或回合完成。

### 取消、重入與減少動態

- `NDCombatFX.play()` 的 Promise 在完成或取消時都要結束；同一 `session:round` 不重播。新局、離開、尺寸變更與分頁隱藏後不得留下動畫、timer、浮字或舊場次回呼。
- 背景取消清除技能佇列及瞬間層；返回可見狀態時以保存的狀態快照同步。不要用動畫結束回呼推進規則；遊戲主流程是唯一回合擁有者。
- `prefers-reduced-motion: reduce` 下省略位移、震動、碎屑、掃光與霧流；保留正面牌、數值、日夜、領域與硬幣結果。現有戰鬥浮字簡化等待為 650ms；免費護盾提示目前為 1100ms。
- 減少動態不等於靜音。不得因媒體偏好更動戰鬥結果、RNG 呼叫數或音訊設定。

## 音訊與本機素材契約

目前所有音訊控制集中在 `game.js`：`AUDIO_URLS`、`AUDIO_DEFAULTS`、`AUDIO_LABELS`、`AudioBank`、`ND_SFX_POOLS`、`playSfx()`、`switchMusic()` 與 `ND_BGM_FALLBACK`。這是共用核心區，任何實作變更都需產品指派。

- 已有三種音樂模式：`setup → setupBgm`、`battle → bgm`、`result → resultBgm`。目前切換淡化為 320ms，SFX 每種類最多使用三個 Audio 物件重疊播放。
- 音量為各 key 的 `0–1` 值，存於 `nightfallAudioVolumesV1`；調整應立即套用基礎 Audio、其播放池與備援音源，恢復預設應一致。全部靜音應涵蓋當下正在播放的音源及稍後才執行的回呼。
- 目前 15 個音訊 key 中僅 `coinFlip` 使用本機 `assets/coinFlip.wav`；其餘 14 個 URL 指向外部站點。本機硬幣的來源註記為 Raventhornn／Freesound #181189／CC0，這是程式中的既有記錄，本次未重新查證來源與授權。
- 新增或搬移本機素材時，交付檔名、格式、長度、用途、來源／作者、授權及轉檔紀錄；保留既有 key，除非產品同時指派所有呼叫點。不得以網路下載成功或 HTTP 200 宣稱已聽測。
- 播放失敗、解碼失敗、使用者手勢限制、靜音與無 Audio API，都必須安全完成，不阻塞 AI、揭曉或結算。SFX 目前 catch 播放拒絕後安靜略過，沒有完整替代音效。
- 既有音樂優先嘗試遠端來源，700ms 後若未播放便嘗試 Web Audio 合成備援，並由使用者手勢解鎖。備援也要遵守模式、音量與靜音，並在原音源恢復、切頁或停止時清理。
- 音畫同步以已成立的呈現事件為準。現況 `damageDirect()` 等規則函式會在結算時先播音效，而可見命中由稍後的 `NDCombatFX.play()` 播放；若要對齊，應由產品分配共用函式與事件入口，防止舊呼叫點和新特效各播一次。

## 與遊戲樹 Agent 的交接契約

規則端產生結果，特效端讀取；雙方透過產品確認介面變更。現有最小介面如下：

```js
NDCombatFX.play({
  session, round,
  result: { player: { events: [] }, ai: { events: [] } },
  pending: { player: card, ai: card }
}); // Promise；完成或取消均須結束
NDCombatFX.cancel();
NDCombatFX.freeShield(amount);

NDEnvironment.sync({ session, p: { night, domainActive }, a: { night, domainActive } });
NDEnvironment.cast(card, side); // side: 'player' | 'ai'
NDEnvironment.playSkills({ player: card, ai: card });
NDEnvironment.cancel();
NDEnvironment.leave();

// 既有事件最小欄位，events 所屬 side 為受影響方：
// { type: 'damage' | 'miss' | 'domain' | 'shield', reason, hp, shield, amount }
// card 的呈現分類主要讀 k 與 job。
```

- `S.roundEvents` 由規則端寫入，結算後複製至 `S.lastResult`；特效不得修改事件、`pending`、`S` 或玩家物件，不引入判定 RNG，不呼叫 `damage()`、`damageDirect()`、`resolveRound()` 或 `nextRound()` 以補效果。
- 目前效果分類部分依 `reason` 是否含「爆擊／灼傷／反擊」；改文案會影響分類。若改為明確事件 key，由遊戲樹 agent 定義規則語意、產品核准介面後再串接，不能只改呈現端猜測結果。
- 新事件交付需提供來源、受影響方、正負數值、是否是實體接觸、顯示順序及確定性範例；閃躲、完全護盾吸收、反擊、灼傷、領域轉換必須能區分。
- 規則端負責固定種子／固定 RNG 的戰鬥案例；本 agent 驗證播放前後狀態與 RNG 呼叫數不變、重播不推進回合、取消會釋放等待。測試中替換 RNG 僅限測試，不得流入演出實作。
- 傷害數值與事件含義有疑問時附上最小案例交回產品；不得以改浮字掩飾狀態差異。

## 與美術／UI Agent 的交接契約

- 使用既有錨點：`.slot.you / .slot.enemy`、`.duel-screen > .duel-side.player / .enemy`、`.retro-arena`、`.card3d > .front / .back`。UI 若改 DOM、座標、transform、z-index、overflow，需提供新錨點與各尺寸示意，並由產品安排相容性驗證。
- 本 agent 提供效果時長、運動路徑、素材透明邊界、層級、裁切與減少動態版本；美術／UI 提供圖示 key、素材來源、卡面比例、視覺樣式與安全文字區。
- 卡片本體 opacity、preserve-3d、backface、紙芯及父層 filter 是共同不變條件；不得只改截圖中的單一影格而破壞翻牌材質。
- 共用 CSS 先列出 selector 白名單與載入順序，再由產品分配唯一修改者；若同時需要規則或 HTML 變更，交付修改提案與必要介面，避免多 agent 同改共用檔。
- 交付至少包含桌面與窄螢幕、正常／減少動態、局部效果與實際操作的對照；效果圖不能取代可點擊性與布局檢查。

## 接單與交付格式

沿用 [README.md](2026-09-25-README.md) 的工單格式，接單補充：觸發事件／角色／卡牌、入口與尺寸、允許修改的函式或 selector、正常與減少動態預期、音量及失敗備援要求。缺少共用檔案分配時先做唯讀診斷與獨立範圍，將依賴交回產品。

## 已確認現況與待查風險

1. **呈現模組已分離，但共用入口仍集中。** `combat-fx.js` 與 `environment.js` 都有只讀定位、取消及減少動態路徑；`game.js` 保有規則、音訊、揭曉、硬幣與環境串接。後續優先將工作分成明確函式／selector 範圍，產品統一整合入口與內容版本。
2. **翻牌規範與舊測試互相矛盾。** `character-art.css` 及 `tests/flip-material.cjs` 要求正反面 opacity 恆為 1；`tests/art-effects.cjs` 的翻牌段仍斷言背面 opacity 為 0。此為原始碼可直接確認的矛盾；建議產品指派測試擁有者將舊斷言改為新材質／實際命中契約，再執行相關測試，不能先宣稱整套通過。舊透明度動畫仍留在 `styles.css`，目前依後載 CSS 覆蓋，載入順序需保護。
3. **音訊仍依賴外部來源，備援與設定可能不一致。** 合成備援的 master gain 固定為 `.055`，目前未見 `getAudioVolume()`／`setAudioVolume()` 接到此 gain；`toggleAudio()` 只 pause `AudioBank`，未見同步停止 `ND_BGM_FALLBACK`、播放池 clone 或 `ndMusicFadeFrame`。這些是靜態盤點的待驗證風險，未進行聽測。建議優先做靜音／音量／失敗備援的集中修復與定向測試。
4. **音效觸發與可見接觸分屬不同階段。** 結算端目前可先觸發 hit、burn、counter 等音效，特效之後才抵達接觸點；是否形成明顯失同步需實際錄製確認。移動音效前須盤點所有規則及免費效果入口，防止漏播／重播。
5. **部分呈現語意依賴文字。** 特效透過 `reason.includes()` 分辨爆擊、灼傷、反擊，翻譯或紀錄文案變更可破壞效果分類。建議由產品安排遊戲樹與本 agent 共同定義穩定事件分類；不在此文件任務順手改介面。
6. **歷史驗收不能代表目前所有入口或裝置。** 既有文件記載外部音效可能 `ERR_ABORTED`、手機多為桌面 Chrome viewport 模擬，未宣稱完整離線音效／實機效能／完整遊戲樹覆蓋。本次不擴大這些歷史結論。
