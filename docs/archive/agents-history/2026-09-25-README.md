## 工作方式

收到需求後，產品建立工單並指定主責；只有可獨立完成、檔案不衝突的工作才平行執行。跨領域需求分為幾張有依賴的工單，先定資料與事件介面，再各自實作，最後整合。可用代理名額不足時依依賴順序排隊，不要求使用者改到其他對話。

例如「夜襲不夠明顯」：產品定義辨識要求，美術/UI 設計狀態標記，特效/音效處理環境轉場，遊戲樹驗證雙刺客與解除條件。劇情只在需要新增文本或世界設定時參與。

「遊戲樹」包含自由決鬥及故事進程，不只畫劇情流程圖。劇情 agent 定義內容；遊戲樹 agent 核對前置、可達性、勝負、失敗、重試、獎勵及存檔結果。

## 工單格式

```text
ID／優先級：
使用者需求與可見成果：
主責／協作角色：
允許修改檔案／本次不包含：
允許函式／區段、修改前基線、單一寫入者與工程師審查位置：
輸入、輸出及依賴：
素材任務：最大顯示區、生成張數與尺寸目標、runtime單檔／總量預算：
驗收條件與必要測試：
交付位置：
狀態：待辦／進行中／待整合／需補正／受阻／完成
```

角色文檔會保留；運行中的 agent 是按需派工，不是常駐服務。下一次派工先提供根 `AGENTS.md`、角色文件及明確工單。是否完成以 [WORKBOARD.md](2026-09-25-WORKBOARD.md) 的驗收紀錄為準。

工程師檢查包含產品整合所寫的程式。交付順序、基線工具與差異處理見 [工程審查流程](../../engineering-workflow.md)；缺少可信基線時如實標記，不能用修改時間推斷誰曾越權。

所有角色的新增圖片都遵守 [美術尺寸與容量規範](../../art-asset-budget.md)，以本地尺寸／容量檢查作為交付條件；不能將生成服務回傳的原圖尺寸直接當遊戲載入規格。
