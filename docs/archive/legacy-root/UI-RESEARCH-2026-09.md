# Nightfall Duel：卡牌戰鬥介面研究與優化提案

研究日期：2026-09-23。對照版本：V12.12.39-Test。

本文件區分官方可確認的事實、現行遊戲量測，以及待驗證的設計提案。這次完成研究與操作示意，沒有修改正式遊戲的 HTML、CSS、JS 或戰鬥規則。

## 建議方向

Nightfall 適合以「角色對決、選牌、揭曉」為核心，手機採直向優先、桌面維持左右對戰。保留目前接近 5:7 的卡牌比例與午夜古金美術；優先改善手牌可操作範圍、揭牌的視覺重量，以及狀態原因的可理解性。

最優先的改動：手機玩家手牌使用完整寬度；對手手牌改為緊湊卡背加明確張數；中央戰鬥卡大於手牌；不可出牌仍可查看原因。

### 對原始研究的補充

- Yomi 2 的 16:10 與 Urban Rivals 的旋轉描述有官方佐證。
- 「常見卡牌寬高比約 0.68–0.75」可作為設計起點，不能當成五款數位 UI 的官方統計。本次沒有逐張量測競品。
- Nightfall 目前手機卡牌為 68×96，桌面為 112×158，比例約 0.708，已接近 7:10。建議整理成單一比例常數，例如 5:7；沒有必要為比例本身重畫美術。
- 畫面寬高比、手機方向、卡牌比例、瀏覽器可用高度是四個不同條件。橫向不等於 16:9，390px 寬也不保證有 844px 的可用高度。

## 2. 現行介面：程式與瀏覽器量測

量測使用 Chrome 無頭瀏覽器，桌面瀏覽器模擬指定 CSS viewport，並非 iOS／Android 實機。初始畫面為 3 張手牌；另以固定 7 張基礎牌與攻擊封鎖狀態檢查密集手牌。讀取的是載入全部現行樣式後的最終尺寸，非單獨某一份 CSS。

| 項目 | 實測／程式證據 | 對操作的影響 |
| --- | --- | --- |
| 390×844 的玩家手牌區 | 寬 174px；對手手牌也分到 174px | 可操作的手牌只得到約半個戰場寬度 |
| 同尺寸卡牌 | 手牌與中央卡槽皆為 68×96 CSS px；旋轉後外接矩形更大 | 中央交鋒沒有比手牌更突出的尺寸 |
| 7 張手牌 | 相鄰卡片水平起點差約 13.7px | 卡片露出的選取範圍很窄；沒有水平捲動不代表容易點選 |
| 玩家／對手資訊 | 各為 174×187，左右並列於上方 | 細長資訊卡佔用高度；可改為對手上方、玩家靠近手牌 |
| 中央徽章 | 約 64×115.4，卡槽高 96 | 回合／VS 徽章比實際戰鬥卡還高 |
| 底部選單 | 高 106px | 可把部分空間讓給選牌摘要與主要行動 |
| 844×390 橫向 | 文件高 800px；手牌區 y≈527、底部選單 y≈718 | 戰鬥核心操作落在第一屏之外；不能只靠寬度斷點 |
| 階段標籤 | 390px 時 `.phase` 的最終 display 為 none | 底部雖有提示文字，但缺少穩定可見、簡短的階段標示 |
| 小卡內容 | `arena()` 與 `revealCard()` 已只輸出圖像、名稱等簡要內容 | 應保留這個資訊分層，不需再做一次「刪除卡面全文」 |
| 禁用卡 | `arena()` 將不可出的卡設為 disabled；`showCard()` 僅開放玩家階段 | 無法點擊禁用卡了解封鎖、職業或技能條件；等待時也無法預先讀牌 |
| 對手手牌張數 | 現行 `arena()` 最多畫 7 個卡背，該區沒有明確張數 | 7 張以上不能只靠卡背數量判斷；應顯示真正張數 |

原始程式參考：`game.js` 的 `arena()`、`renderGame()`、`showCard()`；樣式參考 `card-theme.css`、`prestige-ui.css`、`unified-art.css`、`hud.css`、`arena-finish.css`。桌面同時顯示頂部與中央回合資訊；手機的頂部回合已隱藏，不把兩者混為同一問題。

## 3. 手機資訊架構

建議順序：

1. 頂列：回合、日夜、選單。日夜直接影響刺客，應常駐可見。
2. 對手資訊：小頭像、HP、護盾、手牌張數、有效狀態。
3. 中央決鬥：兩張戰鬥卡左右並列，附清楚的擁有者標籤；VS 縮為小標記。
4. 當前事件：選牌、等待對手、雙方揭牌或本回合結算。
5. 玩家資訊：HP、護盾及當前限制，位置靠近手牌。
6. 玩家手牌：使用完整寬度。
7. 行動區：選牌摘要、詳情入口與一個主要行動。

這裡採「玩家資訊上下分布、兩張戰鬥卡左右比較」。若把兩張 120px 寬的戰鬥卡也上下堆疊，光卡片就需約 336px 高，手機容易再次被擠滿。

桌面可以維持雙方資訊左右對稱，縮短過寬的資訊面板，並放大中央戰鬥卡。短橫向畫面另用緊湊配置，依高度一起判斷斷點；不沿用 800px 高的桌面堆疊。

## 4. 卡牌尺寸與閱讀層級

以下都是待實測的 Nightfall 目標值，以 390px CSS viewport 為基準，不是競品規格。

| 狀態 | 建議起始寬度 | 呈現內容 |
| --- | --- | --- |
| 手牌 | 72–80px | 原畫、名稱、類型、必要狀態；不放完整技能文 |
| 已選手牌 | 優先維持原寬並抬升 12–16px | 外框與固定摘要區標示選取；需要放大時在覆蓋層使用約 100–108px，不推擠整排 |
| 蓋牌 | 108–116px | 所屬玩家、已出牌狀態；不顯露對手資訊 |
| 揭牌 | 120–128px | 圖像、名稱、與本次交鋒有關的效果標籤 |
| 詳情卡圖 | 約 256–280px | 保留卡圖比例；技能全文可放在卡圖外，詳情面板不必硬套 7:10 |

蓋牌與揭牌共用預留的最大槽位，避免放大造成版面跳動。尺寸應依可用容器及高度限制，不只寫 `vw`；低高度或大字模式允許詳情閱讀區捲動，主要操作維持可見。

手牌數量策略：3–4 張盡量完整顯示；5–7 張輕度重疊；更多手牌或較窄畫面提供可展開的手牌面板。以 390px、左右各 16px、卡寬 76px 為例，7 張的水平間距為 `(358−76)÷6=47px`；到了 320px 寬只剩約 35px，需切換展開方式，不能無限加深重疊。

一般觸控按鈕及替代選牌入口以至少 44×44 CSS px 為設計目標；要檢查真正可命中的未遮擋區域，不只檢查卡片的名義寬度。這是專案採用的舒適操作目標；[WCAG 2.5.5 增強級](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html) 使用 44×44，[2.5.8 最低級](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 則是 24×24 且包含例外，兩者不能混稱。

## 5. 行動、狀態與結算

### 選牌不必每次進入完整詳情

目前點牌已可查看詳情並出牌，保留此能力。建議下一版增加輕量選取：點牌 → 抬升與一句摘要 → 確認出牌。另有明顯的「詳情」入口；長按可以是捷徑，但不是唯一閱讀方式。保留拖曳快捷操作，目標區高亮，拖回或放到無效位置不提交。

將「可以閱讀」與「可以施放」分開。封鎖的攻擊牌仍能開詳情，只讓施放按鈕不可用並顯示原因。例如「本回合攻擊被封鎖，可選防禦或閃躲」。等待與揭牌時可以看自己手牌，但不能改動已提交的動作。

### 使用階段相符的單一主要行動

| 狀態 | 畫面與行動 |
| --- | --- |
| 未選牌 | 「選擇一張牌」；主要行動不可用 |
| 選取一般牌 | 摘要＋「確認出牌」 |
| 選取免費護盾 | 「施放護盾・不消耗正常出牌」 |
| 免費護盾已施放 | 「護盾 +2・仍須出一張戰鬥牌」 |
| 已提交 | 「等待對手」；自動揭牌 |
| 結算 | 顯示結果摘要；沿用目前自動進入下一回合的流程 |

Nightfall 的普通出牌本身會推進流程，沒有必要再疊一個「結束回合」按鈕。坦克的免費護盾與一般出牌必須使用不同文案，避免玩家誤以為回合已完成。

### 把狀態寫成可以推理的資訊

- 封鎖：標明本回合限制與解除時機。
- 灼傷：顯示精確數值與觸發時機；遊戲含 0.25 等小數，不應四捨五入成整數。
- 夜襲：除了背景切夜晚，還要顯示當前閃躲牌會轉成攻擊。
- 領域：顯示是否生效、適用效果與失效條件。
- 以圖示、文字和形狀共同表達狀態，避免只靠紅綠或降低透明度。

### 中央只呈現本次事件的重點

保留現有揭牌 → 結算 → 回合推進順序，將浮動數字補成一句可回看的結果。例：「攻擊 1 → 防禦 −0.25 → 承受 0.75」。若有護盾、閃躲、領域、反傷，再依實際結算順序顯示相關節點；這個例子不代表每回合一定扣 0.75 HP。

資料應由實際結算事件產生，不能在 UI 另外重算規則。傷害、吸收、反傷與狀態觸發容易同時出現，需保持先後及來源可追溯。結果摘要至少保留至玩家開始下一次選牌，完整記錄仍放在「戰況」。未揭曉前只顯示已知資訊，不預先暴露對手手牌或隨機結果。

視覺上保留原畫、角色肖像與古金卡框。讓空卡槽、HUD 外框和戰場刻紋退後；最高對比留給已選牌、揭牌卡與主要行動。先釐清焦點，再增加特效。

## 6. 執行順序與驗收

| 優先度 | 工作 | 驗收方式 |
| --- | --- | --- |
| P0 | 手機手牌全寬、對手卡背緊湊化、7 張以上有展開入口 | 320／360／390／430px，3／4／7／10 張牌均能逐張選取；沒有被其他卡完全遮擋的唯一操作入口 |
| P0 | 補上短橫向配置 | 844×390 下 HP、中央交鋒、玩家手牌及主要行動都可到達；基礎出牌無需捲動尋找 |
| P0 | 禁用卡可以閱讀與查看原因 | 封鎖、錯誤職業、已施放護盾、領域條件各有明確原因，且不能繞過施放限制 |
| P1 | 放大揭牌卡、縮小 VS、整理雙方 HUD | 玩家一眼能指出自己的手牌、生命、目前階段與本次兩張戰鬥卡 |
| P1 | 輕量選取、單一主要行動、免費效果文案 | 不看規則也能完成一次一般出牌，以及「免費護盾後再出牌」 |
| P1 | 結算摘要與狀態時序 | 新玩家能解釋自己為何扣血、扣盾或不能攻擊；摘要與實際事件一致 |
| P2 | 動畫節奏與美術精修 | 尊重減少動態設定；快轉或略過表現不得漏掉結果或重複推進回合 |

建議找 5 位未玩過的新玩家做探索性測試，觀察首次成功出牌時間、誤觸、詳情開關次數，以及能否說明上一回合結果。這些先建立基準再比較，不預設尚未量得的提升百分比；小樣本只能發現問題，不能證明統計上的改善。

測試矩陣還應包含 390×667、手機瀏覽器工具列收合／展開、安全區、大字模式、鍵盤操作、多重狀態與低血量。現有測試常以 1000px 高度檢查多種寬度，應補充真實可用高度；本次研究沒有重跑完整遊戲測試，也沒有宣稱完成實機驗證。
