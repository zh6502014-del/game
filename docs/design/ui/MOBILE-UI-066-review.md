## 已確認問題（均已於第二次補正關閉）

### P2｜可用高度不足時，決鬥的 HUD 遮住下方棋盤／牌背

- 位置：`src/css/mobile-layout.css:179`，同時涉及 121–126 行中央棋盤固定高度與 193–194 行手牌尺寸。
- 重現：新 context 的 568×320 手機橫向，自由決鬥開始。不加狀態時 HUD 底部 83.9px、出牌槽頂部 76px 已重疊；給 DOM 加入五個合法外觀狀態標籤作展示 fixture 後，狀態列為 y76.9–105.9、HUD 到約 112.9，出牌槽仍 y76–166。回合標題及槽上緣被 HUD 蓋住，槽下緣又進入 y161 起的手牌區。
- 證據：`/tmp/mobile-review-568.png`；獨立 Chrome 實測輸出記於審查工具結果。這是 320×568 手機旋轉後的常見尺寸，不是遊戲規則 fixture；無改動真實存檔。
- 原因：94px 的中央最小列＋94px 手牌列占用有限高度，剩餘的 auto HUD 列縮得小於內容；`overflow:visible` 讓內容跨列。僅驗元素在 viewport 內會漏掉這個遮蔽。
- 同因分支：320×480 短直向（例如小手機瀏覽器工具列占用可視高度），166 行 portrait grid 同樣把 HUD 列壓到小於內容：HUD 底部 135.5px、敵方牌背區卻從 104.2px 開始，敵方手牌數被遮住。截圖 `/tmp/mobile-review-320-short.png`。獨立新對局即重現，未加 DOM fixture。
- 建議：較短橫向高度設計足夠的三區高度／尺寸或合理捲動，保留主要 44px 控制；新增 568×320 HUD、槽／回合、手牌之間不互遮的定向驗收，再驗較大橫向及直向回歸。

### P2｜568×320 故事閱讀的下一段控制被視窗底部裁切

- 產品新增七尺寸主驗收於首次補正後發現，工程師核對失敗 JSON 與 `568x320-failure-after.png` 確認畫面：A1 首段，閱讀按鈕 y293.2–337.2，viewport 高 320，無法完整顯示 44px 點擊區。
- 位置：`src/css/mobile-layout.css:35` 起的故事閱讀固定全高區與 198 行橫向 bottom panel 限高，並受既有 620px 寬度 header 換行影響。
- 影響：小手機橫向的閱讀主操作落在螢幕邊界外；與本工單「閱讀不超 viewport、主要按鈕可及」不符。
