# 美術素材尺寸與容量規範

生效：2026-09-24，ART-BUDGET-007。適用所有 agent 後續新增／替換的圖片，包括劇情、特效、美術與 UI。使用者要求避免過大的生成尺寸、資源浪費與專案肥大。下列為交付上限，不是要求每張圖都做到最大。

## 目前原稿存放方式（2026-10-07）

ART-STORAGE-063 將既有原稿無損封存於 `storage/source-art.tar.gz`，清单為 `storage/source-art-manifest.json`。需要改圖／生成衍生檔時先於根目錄執行 `python3 scripts/source-art-archive.py restore`，還原到 `storage/source-art/`；原稿的圖片像素、原始bytes及生成紀錄均保留。下方早期原稿路徑 `source-art/` 現已對應 `storage/source-art/`。新增原稿仍應只保留一份，完成後的重新封存必须涵蓋新修改，不能沿用舊封存當備份。

## 先確認用途，再生成

1. 先找現有可共用素材。相同地點共用背景、角色與光影分層；同一張卡在手牌、拖曳、翻牌和詳情共用素材。不得為每個節點、畫面尺寸或重複狀態再生成整張大圖。
2. 工單寫明實際最大 CSS 顯示區、比例、是否透明、生成張數、生成尺寸目標、遊戲載入尺寸／容量及新增總量。產品依現有用途定案，不把例行尺寸決策交回使用者。
3. 新生成預設單張、單一候選；沒有構圖／內容問題，不為縮圖或轉格式重新生成。不預設 4K、8K、超採樣或多候選批次。
4. 小型物件要求約 512×512；卡面／角色要求約 1024×1536；寬景要求約 1536×864（或工具最接近的標準橫向比例）。圖示沿用 SVG；單純框線、光影與狀態優先沿用既有程式／向量，不以生成大圖取代。
5. 內建 imagegen 目前沒有可指定精確寬高的工具參數：上述尺寸只能寫入提示詞，**不能保證服務採用該解析度或因此減少生成計費／運算**。生成後讀取真實尺寸和 bytes；較大的輸出保留一份原稿，交付另製適用尺寸。不得為尺寸控制擅自切換 CLI／API／模型，也不為尺寸不符反覆生成。

## 遊戲載入檔預算

尺寸保持長寬比，取滿足實際顯示需求的較小值；最多考慮約 2 倍顯示像素，再受下表上限約束。不拉伸、不把小原圖放大至上限。KB 以下均用 KiB（1024 bytes）。程式化上限以 [art-budgets.json](../config/art-budgets.json) 為準，長／短邊限制不限定橫直方向。

| 用途／分類 | 建議尺寸／最大尺寸 | 單檔上限 | 格式與注意事項 |
| --- | --- | --- | --- |
| 基本／職業／特殊卡、牌背 `card` | 512×768 以內；牌背保留原 5:7 | 250 KiB | 不透明 WebP 優先；縮小後主體輪廓、卡背紋樣仍清楚 |
| 選角／外觀共用肖像 `portrait` | 640×960 以內 | 250 KiB | 可與 HUD 共用，不為每一個入口複製一份 |
| 已裁成臉部的獨立頭像 `avatar` | 256×320 以內 | 80 KiB | 從原畫製作；須配合新的裁切映射，不得再次套用整張原畫的放大值 |
| 硬幣 `coin` | 256×256 以內 | 80 KiB | 保留 alpha；真實材質與薄側緣由元件分層 |
| 背景／故事插畫／地圖 `background` | 通常 1536～1600px 寬；最高 1920×1080 | 600 KiB | 不透明 WebP 優先；禁止放大原稿去湊 1920 |
| 劇情透明人物 `actor` | 768×1152 常用；最高 854×1280 | 450 KiB | 保留 alpha，不加底色；850 CSS px 高約 1.5×，不是全高 Retina 2×保證 |
| 共用九宮格 atlas `frame` | 1024×1024 以內 | 350 KiB | 透明 PNG／無損 WebP；角落不變形 |
| 九宮格切片 `slice` | 長邊 ≤512、短邊 ≤128 | 60 KiB | 比例／切線由 manifest 管理，不單獨縮圖造成接縫 |
| 尋物／拼圖透明道具 `prop` | ≤512×512 | 100 KiB | 共用場景／詳情／拼圖；alpha 不含投影光暈，詳情最大256 CSS px |
| Icon／紋章 `icon` | SVG 優先；點陣圖 ≤256×256 | 20 KiB | SVG 只查容量，viewBox 不是點陣解析度 |

原始生成稿 `source` 預設上限：長邊 2048、短邊 1536、5 MiB。此值是生成後異常檢查上限，不是提示詞的預設輸出尺寸。工具回傳超過上限時記錄實際值與理由；先完成小尺寸遊戲載入檔，不因超標刪除原稿或盲目重生。

目前桌面卡片約 112×158、詳情插畫高約 190～360 CSS px；硬幣約 88～108px；HUD 肖像約 96×116px，手機約 56×70px。HUD 的整張原畫裁切會放大 225～255%，所以保留現有 `faceCrops` 時應使用 `portrait` 檔，不是把整張角色直接縮成 256×320。獨立臉部衍生檔需另行校準映射；不得為節省容量讓五官變糊。整張 1024×1536／1254×1254 的多 MB PNG 不應直接成為這些元件的新載入檔。故事人物可高達 850px，不能套用小頭像預算；若實際 1.5× 檢視出現臉部細節不足，由產品記錄必要的 1536px 高局部例外，不全套升級。

超標例外由產品在工單列明必要顯示尺寸、不能壓縮的證據、增加量與上限後處理；不需要使用者反覆確認一般例行輸出。不得為取得綠燈把 runtime 圖假分類為 `source` 或全域提高預算。

## 原稿、衍生檔與專案容量

- 後續選定的原稿只存一份至 `source-art/<工單>/`；遊戲引用的最終檔存 `assets/<用途>/`。來源記錄保留工具模式、完整提示詞、參考圖、原稿 SHA-256、實際尺寸／bytes、衍生檔路徑／尺寸／bytes／轉檔設定。未選用的候選不再複製進專案。
- 打包遊戲時只納入實際引用的 runtime 與必要備援，不包含 `storage/source-art/`、測試截圖、備份或未引用歷史版本。這是後續打包規則；本輪沒有建立或修改發佈腳本。
- 保留既有原稿與生成紀錄；本輪不搬動、刪除、重新生成或改寫現有素材映射。既有 legacy 檔案目前仍混在 `assets/`，不能宣稱已分離或壓縮。
- 縮圖和格式轉換屬衍生輸出；按使用者已授權的尺寸／容量優化範圍處理，保持內容、比例與 alpha。透明邊緣、漸層、臉部與金屬細節必須用實際畫面檢查。不要只以檔案小作為品質通過。
- 素材上限也包含總量：工單以「數量 × 單檔預算」設定新增 runtime bytes，另列原稿 bytes；完成時交付實際增量。禁止以每張都未超標為理由無上限補圖或複製舊檔。測試報告保留必要證據，不為每次檢查複製整份素材目錄。

## 每次交付的必跑檢查

以下為只讀工具，沒有縮圖、轉檔、搬移或刪除功能，不需要安裝套件：

```sh
# 盤點所有現存 assets；退出 0 只表示完成盤點，並非驗收通過
python3 scripts/check-art-budget.py

# 新增／替換 runtime 的交付閘門；傳入本工單的每個檔案或目錄
python3 scripts/check-art-budget.py --strict assets/cards/new-version/

# 新用途尚未登錄路徑時，明示用途；正常應補 config 的 path rule
python3 scripts/check-art-budget.py --strict --kind actor assets/new-actors/hero.webp

# 選定的原稿另外檢查，不能用這個指令替代 runtime 驗收
python3 scripts/check-art-budget.py --strict --kind source source-art/ART-XXX/

# 輸出完整可追溯的尺寸與容量盤點
python3 scripts/check-art-budget.py --json > test-results/art-budget-audit.json
```

`--strict` 超尺寸／容量退出 1；未知分類、缺檔、未知格式／無法讀取標頭退出 2。PNG／JPEG／WebP 讀尺寸標頭；SVG 查有效根元素與 bytes。AVIF 等尚未支援的格式會報錯，不能默默跳過。這不是完整解碼、圖片品質、runtime 引用可達性或實機效能測試；替換素材仍需瀏覽器檢查。

美術交付附：工單 ID、生成張數、每張來源與實際尺寸、runtime 尺寸／bytes、新增總量、strict 指令與結果、縮放後畫面證據。產品驗收不接受只報「原圖生成完成」。
