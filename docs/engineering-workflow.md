# 工程審查流程

生效：2026-09-24，ENG-REVIEW-001。工程師角色：[ENGINEER.md](agents/ENGINEER.md)。適用所有 agent 及產品自行整合的後續程式碼修改；使用者仍只在產品主對話提出需求。

## 工單生命週期

1. **產品定範圍**：記錄需求、唯一寫入者、允許檔案及函式／區段、不得改動的規則／介面、相關測試；原始檔、測試、自動生成入口版本各列負責人。
2. **動工前留證據**：有 Git 時保留明確基準 commit 及工作樹狀態；本專案目前沒有 Git，使用下方工具保存全體文字程式檔雜湊，以及本工單允許檔案的原文。不備份整個圖片目錄。
3. **實作／凍結**：執行者只修改工單範圍，跑對應驗證，交付實際改動與未驗證事項，通知已停止寫入。若範圍改變，由產品記錄理由、重派範圍並保存追加基線；不要覆寫原來證據。
4. **工程師獨立審查**：核對新增／修改／刪除、允許檔案內的真實 diff、規則與存檔保護、重複／死碼、錯誤處理、取消清理、安全渲染、測試品質。不把個人格式偏好當作缺陷；不能只看測試綠燈。
5. **補正／複審**：有證據的越界或本次範圍相關 P0／P1／P2 先派回唯一寫入者；工程師核對原重現及新差異，必要測試通過後再交產品。範圍外舊問題另立工單，保留風險，不偷偷擴大重構。
6. **產品驗收**：最終版本與素材檢查由指定整合者序列執行；工程師給出可交付／需補正／證據不足，產品對外一次回報並維護工作板。

單純文件與原畫任務按影響範圍驗收，不要求每次開全套瀏覽器。工程師按需喚起，不是背景守護程式；本工具也不是自動阻止寫檔的權限沙箱。

## 複審與重跑的最小充分流程

2026-09-24，ENG-EFFICIENCY-002。保留獨立工程審查與原交付門檻，減少重複讀碼、日誌及驗證。

1. **先列驗證範圍**：產品在工單列出受影響行為、測試命令、唯一執行者及證據位置。長流程先做載入、定位器、一次主要操作的短檢查，確認測試環境可用再跑完整案例。
2. **共用一次有效證據**：實作者交付來源與相關依賴、測試程式／輸入、執行環境及設定的版本或雜湊，附命令、結果與產物路徑。工程師核對真實 diff、測試品質並獨立驗證關鍵風險；產品負責需求與視覺驗收，不機械式各跑一遍相同套件。
3. **集中補正、差異複審**：初審集中交付已確認問題；P0／P1 立即通報。修正後讀新 diff、重現原故障並跑受影響回歸。未改動區域沿用仍有效的證據；發現新風險則擴大檢查，不以輪數上限省略必要修正。
4. **先分類失敗**：區分產品缺陷、測試程式／定位器錯誤、環境或權限失敗。修正測試後重跑失敗案例及受該修正影響的案例；不能放寬行為斷言換取通過，環境失敗也不能記作產品通過。
5. **凍結後整合一次**：整合者序列更新版本並驗證。其他工單變更依賴時，只使受影響證據失效，記錄交接主責；不得拿舊快照宣稱目前整個專案通過。

證據沿用的前提是相關來源與相依程式、測試／資料、環境與設定未變；只有單一檔案雜湊相同不夠。無法判斷影響面、證據缺漏或有不穩定結果時，補查依賴並擴大驗證。以下是選測起點，不能取代工單的明確驗收要求：

| 改動範圍 | 必要驗證起點 |
| --- | --- |
| 文件、註解 | 內容一致、連結及差異範圍；通常不跑瀏覽器 |
| CSS／版面 | 受影響尺寸、溢出、數值重疊、點擊區與主要操作；共用樣式需查其他使用入口 |
| 拖曳、非同步與生命週期 | 受影響的滑鼠／觸控／鍵盤操作、取消、多指、退出、重試及整合流程 |
| 引擎、AI、RNG、存檔或公開介面 | 完整相關規則／相容性套件，加受影響整合案例 |

例如只移動故事戰鬥護盾徽章，仍須檢查受影響版面與重疊；引擎及相關依賴未變且證據完整時，可沿用規則與 RNG 測試結果。若修改共用傷害介面，就必須重跑相關規則與整合驗證。

交接只提供工單範圍、基線、變更摘要、問題清單與證據路徑；按需讀相關區段，不重複載入完整工作板或歷史對話。工具回傳摘要與失敗片段，完整日誌／diff 留在檔案。審查報告分列「本次實跑」「沿用證據及依據」「未驗證」，不將沿用寫成本次重新執行。

WORKFLOW-EFFICIENCY-004 提供 [導航／選測與證據工具](workflow-tools.md)：`map` 先列目錄，`plan --changed` 提供保守候選，`run` 隔離執行允許的套件並保存完整日誌，`inspect` 核對證據是否仍相符。地圖須隨介面更新；未知影響擴大候選，瀏覽器仍需工單獨立環境。這是人工審查的輔助，未建立自動略過測試的快取，也不取代本流程的必要驗收。

## 無 Git 時的差異工具

工具：[check-change-scope.py](../scripts/check-change-scope.py)，只使用 Python 標準庫。範例工單需替換為實際 ID 與產品已核定的精確檔案清單，**先 snapshot 再修改**：

```sh
python3 scripts/check-change-scope.py snapshot \
  --ticket TASK-ID --owner art_ui \
  --allow card-art.js --allow tests/art/unified-art.cjs \
  --output test-results/change-scopes/TASK-ID-before.json

python3 scripts/check-change-scope.py check \
  --baseline test-results/change-scopes/TASK-ID-before.json --diff --json \
  > test-results/change-scopes/TASK-ID-after.json
```

- `--allow` 每次一個精確的專案相對檔案路徑，可重複；不接受整個目錄或 `../`。允許列尚未建立的新檔。函式／區段授權仍由人工比對 diff。
- snapshot 不覆寫現存基線。原文只保留允許的文字檔，其他受追蹤檔保留 SHA-256；目的是低容量留證，不重複存整套遊戲／圖片。凍結交付後保存 after 報告。
- 追蹤 JS／CJS／MJS、CSS、HTML、Python、JSON、Markdown、SVG、TOML、YAML、shell。排除 Git／代理設定／依賴／快取、`test-results/`、`storage/backups/`、`storage/source-art/` 及 `.backup.` 檔案；二進位素材另走美術容量及素材映射審查。排除項與副檔名完整記於基線。
- 未排除的符號連結檔案或目錄要求人工審查，工具不跟隨它們。掃描過程中檔案若改變，要求停止寫入後重試。
- `check` 退出 **0**：追蹤到的最終差異只在檔案清單內；**1**：有清單外差異，`REVIEW_REQUIRED`；**2**：證據／路徑／讀取問題，不能當通過。
- 檔案在清單內不代表改動合法。工程師還要讀 diff，尤其呈現層不得偷改 AI、傷害、RNG、回合與存檔。工具不驗證語意，不能拿 exit 0 替代 code review。
- 多張工單並行時，清單外差異可能來自另一個已授權任務。產品核對工作板、寫入者與凍結時間，在審查紀錄逐項歸屬；**不反向擴大原白名單讓工具變綠、不擅自還原別人的檔案**。來源不明則待釐清。
- 不提供持續監控／作者認證／防竄改保證；修改後又復原的中間動作不在最終差異內。缺少任務前基線的舊工單只能審查當前程式，不宣稱歷史沒有越權。
