# Agent 分工入口

使用者 → 產品 → 本次主責 → 工程師審查／必要補正 → 產品驗收。角色是專長與權責，不代表常駐程序；使用者不需轉到其他對話。

| 角色 | 入口 | 負責問題 |
| --- | --- | --- |
| product | [產品](PRODUCT.md) | 範圍、依賴、唯一寫入者、整合與驗收 |
| art_ui | [美術／UI](ART-UI.md) | 可讀性、布局、素材及操作 |
| fx_audio | [特效／音效](FX-AUDIO.md) | 事件演出、音畫同步與清理 |
| story | [劇情](STORY.md) | 世界、人物、文字與揭露次序 |
| game_tree | [遊戲樹](GAME-TREE.md) | 規則、狀態、可達性、保存與恢復 |
| engineer | [工程師](ENGINEER.md) | 真實差異、品質、風險與驗證 |

先讀根 [AGENTS.md](../../AGENTS.md)、自己的入口及工單；按[工具導航](../workflow-tools.md)找必要程式。工作板只留[現況與索引](WORKBOARD.md)，工單保存完整結論；不在角色文件、工作板、交接中各抄一次全文。

## 精簡工單

```text
ID／可見成果／完成條件：
唯一主責／精確可寫檔案與區段／整合者：
必要限制／本次不含／未決問題：
相關入口、輸入／輸出介面及依賴：
修改前基線／工程審查位置：
必要驗收、命令、唯一執行者及證據位置：
素材任務才填：用途／張數／尺寸／runtime單檔及總預算
狀態／下一步負責人：
```

通常由一名主責實作，獨立工作才平行；共享檔排順序。程式修改含產品所寫部分，均依[工程流程](../engineering-workflow.md)留基線及獨立審查。新圖片另讀[素材預算](../art-asset-budget.md)。缺少重要產品方向才詢問使用者，已授權的可逆工作直接推進。

交付只述改動、問題、證據與限制；完整日誌落檔。不能將測試候選清單當成已通過、舊證據當成本次實跑或子 Agent 回報當作產品驗收。
